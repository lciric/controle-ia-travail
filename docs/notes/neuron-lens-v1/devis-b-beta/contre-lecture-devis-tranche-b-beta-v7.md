## Verdict

**À corriger** : 0 bloquante, 4 majeures, 15 mineures.

L'arithmétique de la dépense est juste (pire cas, arrêt dur, minuterie, trafic), le relevé neuf est exact ligne par ligne, et les
gardes de dépense citées existent dans le code avec les options annoncées. Mais le devis se contredit sur la disponibilité (un
passage de la v5 est resté tel quel après le relèvement du prix exigé), la décision ne dit pas ce qu'il faut à Lazar sur le plafond
monté de 68 à 88 USD, le lieu recommandé pour les lentilles suppose un second secret sur la machine louée sans le dire, et la règle
d'arrêt après le banc de montage a disparu.

## Vérifié et trouvé conforme

**Relevé neuf (ligne par ligne).** Formule `dph_total + storage_cost × 200 / 720` : 4,0366 + 0,6640 × 0,2778 = 4,2211 ; 4,0367 + 0,6800 ×
0,2778 = 4,2256 ; 4,0433 + 0,6640 × 0,2778 = 4,2277 ; 1,9343 + 0,1333 × 0,2778 = 1,9713 : les sept lignes sont justes. Exigences :
les six lignes de Tchéquie échouent sur le prix (> 3,00) ; la ligne du Japon échoue sur le débit montant (97 < 200) : « non » partout
est juste. Comptes de l'en-tête du relevé (2, 2, 3) conformes aux lignes. Texte du devis conforme : témoin ≈ 4,22 et ≈ 4,23 ; filtre
complet ≈ 4,23, débits 7 127 et 8 358, trafic ≤ 0,0391 ; Japon ≈ 1,97, non vérifiée, 97 Mbit/s. Le script n'appelle que
`search offers` (lecture seule), `--limit 64` écrit, balayage avant écriture.

**Relevés anciens.** Tableau du § 3 contre `releve-prix-vast-20261117T002223Z-v1.tsv` (`1a7cc32c…`) : nombres d'offres, plages de prix
et de trafic de chaque ligne conformes ; prix avec stockage 2,145, 4,83, 5,03, 2,415 justes. Relevé de 01:23Z (`8814fec4…`) : aucune
ligne d'offre. Relevé de 01:27Z : Montana 2,3403 → 2,6181, 1 571 Mbit/s, 0,0391 et 0,0195, fiabilité 0,9949 : conformes.
