### 3.2 EVOSCM — Zhao et al., arXiv 2609.01526 v2, et code au commit `ffb63899…` (banc de physique seulement)

- **(i).** Les candidates et leurs prédictions viennent du modèle de langue sur le banc de physique ; sur le banc de matériaux, « Each hypothesis is a bootstrap sparse ridge mechanism fitted independently for each property outcome. » (p. 29). Statut : **pris** (physique), voisin ailleurs.
- **Poids.** Uniformes au premier tour (« with uniform evidence weights, irrespective of any confidence values reported by the LLM », p. 27), puis, pour une candidate ajoutée plus tard, logarithme de la confiance déclarée par le modèle (lecture I, `scm_pipeline.py` l. 3281-3285, confirmé par J). Calculés par le programme : log-vraisemblance gaussienne bornée, « log_likelihood = float( -0.5 * z_score**2 - math.log(prediction["sigma"]) ) log_likelihood = min(max(log_likelihood, -50.0), 20.0) » (`scm_pipeline.py` l. 4030-4033), rendue relative au meilleur groupe de la même cible, « relative = (group_scores[root] - best) * causal_weight » (l. 4123), où le score d'un groupe de prédictions voisines est le meilleur de ses membres, « group_scores = { root: max( ( float(target_records[index]["log_likelihood"]) for index in indices ) » (l. 4106-4112), puis tempérée, « relative_log_evidence = ( float(np.mean(relative_values)) * math.sqrt(len(relative_values)) * self.evidence_temperature ) » (l. 4132-4136), et cumulée. **Correction (constat 2)** : entre deux hypothèses qui prédisent les mêmes cibles sans être regroupées, le terme du meilleur s'annule dans la différence, et l'écart de leurs log-poids est une somme, plan par plan, de logarithmes de rapport de vraisemblance gaussien multipliés par 0,7 divisé par la racine du nombre de cibles du plan (mon calcul sur ces lignes) ; c'est donc un rapport de vraisemblance gaussien cumulé et tempéré entre lois engagées avant l'observation. La phrase de la lecture *ni un rapport de vraisemblance cumulé* est retirée. Ce qui l'éloigne d'une e-valeur, sur pièce : aucune hypothèse désignée comme nul, référence au meilleur choisie après l'observation, incertitude déclarée par le modèle, regroupement qui donne au membre le score du meilleur du groupe, bornes, pénalité de complexité, confiance déclarée en entrée après le premier tour, aucun seuil relié à un taux d'erreur. Le PDF ne dit pas comment les poids sont calculés ; il montre des « Posterior odds: finite / vanishing » (p. 18).
- **Règle de retrait** (la plus proche d'une règle séquentielle à seuil) : « return len(distinct_designs) >= 3 and cumulative <= -3.0 » (l. 3423) ; elle décide un retrait, non une promotion, sans garantie.
- **P et (ii) à la finalisation (constat 1).** Quand la loi rendue par le modèle échoue au contrôle causal, le programme compile une loi de famille connue ajustée par lui (« if not initial_causal_pass: compact_compiler = getattr( self.scm_pipeline, "deductive_compactified_law", None ) », `agent.py` l. 842-845 ; décrite comme « canonical Kaluza-Klein image-sum central law with one compact dimension », `scm_pipeline.py` l. 2131) et la substitue si son rang est meilleur : « elif self._final_check_rank(deduced_check) > self._final_check_rank( best_check ): best_law = deduced_law best_check = deduced_check » (`agent.py` l. 897-901). Pour les lois modulées dans le temps, quand plusieurs alias existent (« ambiguous_time_aliases = len(time_deductions) > 1 », l. 829), la loi du programme remplace celle du modèle sous un seuil sur la perte de rejeu, même si celle du modèle passe le contrôle : « select_alias = bool( not initial_causal_pass or not math.isfinite(initial_loss) or selected_loss <= 0.995 * initial_loss ) » (l. 919-923), perte prise sur les données déjà recueillies (« "selection_method": "minimum existing paired-trajectory loss among causal-compatible odd-harmonic aliases", », l. 946). Le contrôle se durcit quand une famille est identifiée : « mechanism_consistent = bool( not strongly_identified_mechanism or max_radius_median_error is None or max_radius_median_error <= 0.3 ) » (`scm_pipeline.py` l. 1892-1896). L'invite pose le principe de comparaison au modèle emboîté : « An extra drag, screening, hidden class, or other mechanism should survive only when it predicts interventions better than the simpler nested model. » (`scm_protocol.md` l. 182-185). C'est une proposition de modèle de langue jugée par le programme contre **une** loi connue ajustée, en fin de course, en échantillon, sans garantie, dans le sens *le connu remplace la proposition* ; ce n'est pas un nul formé d'une archive mise en commun. Statuts : P **voisin**, (ii) **voisin (lointain)**, tous deux précisés.
- **Banc de gènes, PDF seulement (constat 3).** « The archive retains every valid unique graph produced during the four rounds » (p. 31) ; classement « by five-fold grouped cross-validation using the mean held-out squared log error » (p. 32) ; « This selector uses neither the target graph nor evaluator metrics, and makes no additional LLM calls or simulator experiments. » (p. 32). C'est une règle de promotion finale calculée hors du modèle de langue, sur une archive des candidats de la séance, par une erreur hors échantillon ; ni nul de lois connues, ni e-processus ; code absent du clone.
- **Banc de matériaux, PDF seulement (constat 4).** « A frozen library of textbook structures » (p. 30) sert de témoins, dont les résultats « are not presented as novel discoveries » (p. 30). Seuil de fiabilité : « Outcome-specific edges are withheld from the planner when their calibrated reliability falls below 0.20 » (p. 29), et vocabulaire de promotion : « composition-related mechanisms are promoted » (p. 18).
- **(iv-a).** Sur le banc de physique les données n'existent pas avant l'expérience (« Observations are generated on demand rather than retrieved from a fixed dataset. », p. 23), dans un monde simulé (« Our evaluation focuses on simulated scientific environments. », p. 10) ; les prédictions sont prises avant l'issue (« These predictions are recorded prior to experimentation », p. 5) par l'ordre du programme. Aucun scellement : la fonction d'empreinte « def _canonical_sha256(value: Any) -> str: » (`scm_pipeline.py` l. 38) n'est appelée nulle part (constat confirmé par la contre-lecture), alors que « import hashlib » figure aussi en l. 3 de ce fichier.
