## 5. Constats

1. **Mineur — EVOSCM, le calcul de la section 3.2 et du point 6.2-2 oublie un facteur.** La note écrit que l'écart des log-poids est une somme de logarithmes de rapport de vraisemblance *multipliés par 0,7 divisé par la racine du nombre de cibles du plan*. Les lignes qu'elle cite portent un facteur de plus, par cible : « causal_weight = ( 1.0 if target_records[0]["target"].startswith("/paired_effects/") or self.observation_noise_std == 0.0 else 0.25 ) » (`scm_pipeline.py` l. 4116-4121). L'exposant vaut donc 0,7 divisé par la racine, multiplié par 1 ou par 0,25 selon la cible ; et 0,7 est une valeur par défaut d'un paramètre, « evidence_temperature: float = 0.7, » (l. 534), non une constante. Effet : aucun sur le statut *voisin (proche)* (l'exposant reste entre 0 et 1, le calcul reste fait par le programme) ; la phrase du nœud 3 (*tempéré*) reste exacte. À corriger à la lettre, parce que la note présente ce passage comme son propre calcul.
2. **Mineur — le refus partiel d'EVOSCM 7 ne cite pas l'erratum du contre-lecteur.** Le contre-lecteur a corrigé lui-même cette phrase dans `contre-lecture-lecture-entiere-evoscm-o4-v1-erratum-1.md` (heure déclarée 2026-11-18T02:18:37Z, avant le début de la v3), avec la même ligne de l'essai. Le refus est exact sur la note scellée, mais il porte sur une phrase déjà retirée par son auteur ; le bilan *2 acceptés sur le fond et refusés en partie* grossit donc d'une unité le désaccord réel. À écrire : renvoi à l'erratum, et *constat corrigé par son auteur*.
3. **Mineur — WAHL, (iii) : deux bornes manquent à *l'arrêt ne joue pas dans les expériences versées*.** (a) Les seize fichiers de `config/experiment/` ne contiennent aucun fichier pour le banc rénal (aucun nom de fichier de `config/` ne le porte) : la phrase ne vaut par ces fichiers que pour deux bancs sur trois. (b) Le code a un second critère d'arrêt, par seuil sur le poids du meilleur, « if termination_val is not None: » (`modelsmc.py` l. 1631), que la note ne mentionne pas (la lecture entière le mentionnait). Relevé de ma part, qui confirme la conclusion de la note : la clé de seuil est nulle dans les seize fichiers et dans les fichiers de tâche des deux bancs, « termination_val: null » (`config/task/allen_base.yaml` l. 6 ; `config/task/SIR_base.yaml` l. 4) ; dans les configurations enregistrées avec les résultats de la méthode, banc rénal compris, les deux clés d'horizon sont égales et la clé de seuil est nulle dans chaque fichier relevé (chemins non recopiés ici : ils portent le nom d'un modèle de langue commercial) ; seule la méthode de comparaison y a un arrêt sur stagnation plus court que l'horizon. La conclusion tient ; la preuve écrite doit dire d'où elle vient pour le troisième banc, et nommer le second critère.
4. **Mineur — trois affirmations de la section 5 sans page ni ligne (R7, forme).** *95 signaux, quatre versions, fin 2024* ; *seuil d'ESS relatif à N dans le code* ; *τecon et τfail sans valeur*. La troisième est une absence : j'ai retrouvé les symboles dans le texte du PDF de BEYOND, je n'ai pas revérifié qu'aucune valeur n'y est donnée (non vérifié par moi, à la profondeur de cette vérification).
5. **Mineur — une phrase d'en-tête un peu large.** *Aucun nom de modèle de langue commercial n'est recopié* est exact pour la note ; la liste d'extraits de code porte, dans un chemin de fichier d'expérience, le nom abrégé d'un modèle commercial d'une autre lignée.
