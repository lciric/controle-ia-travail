OSF Projects Transition: Registration Questions and Use Cases

OSF Registrations and preregistrations will continue as part of OSF’s ongoing services. This guide answers common questions about creating and managing registrations.


Use cases


Use case We used to register protocols through projects, now will we have to change for registries?
Impact Sharing a protocol in an OSF project will not be available after Feb 2027. We recommend using the registration workflow to register the protocol in the OSF Registry to receive a time-stamped record and DOI for your protocol. See more on the registration workflow in OSF Registry here.
Recommendation Nothing is needed, Registrations are unaffected by the OSF Transition. Continue creating new registrations through the OSF Registration workflow after new projects can no longer be created. An OSF Project is not required to create a registration.
Use case This feels pretty challenging for projects that have been preregistered but have not yet come to fruition. How can we link from the existing project data OUT to other resources?
Impact For projects with a preregistration, you have the ability to add research outputs to your registration using Open Practice Badges , where you can get DOIs for publications or add DOIs from data added to another repository like Zenodo. We recommend sharing outputs at a repository  and then link the provided DOIs to your preregistration as described in this Guide . Before the project becomes read-only in Feb 2027, you can add additional links to the wiki or project description to make them available for visitors to the project to know where they can find additional resources.
Recommendation For preregistered studies you can still Update and add Research outputs, these processes are not affected by the OSF transition.
Use case I have 3 systematic reviews with you. What does that imply for me with these changes?
Impact If those systematic reviews were published on OSF using the registration workflow and/or the Systematic Review Template, they will not be impacted by the changes. If the reviews were uploaded as a file in a project, we recommend registering them using the Systematic Review Registration Template.
Recommendation Nothing is needed, Registrations are unaffected by the OSF Transition.
Use case How about creating components to create view-only links for anonymized peer-review alongside preregistrations? Will I still be able to create components and view-only links to materials I like to share with a preregistration?
Impact You will no longer be able to create new components or projects after November 16; view only links are able to be created/deleted by project admins after February 2027, Read-only Project description. Additionally, you can still create view only links for your embargoed registrations as you do now. And this is also true for a registered component. See this help guide for how to Create a View-only link for a Registration. 
Recommendation An administrator on the registration can create the link through the contributors section. Select the anonymized option when needed.. The OSF Registration guide includes instructions for creating view-only links.
Use case I sometimes worry about storing research protocols, specifically regarding the word count that might be flagged by Turnitin as self-plagiarism. What would you recommend?
Impact Turnitin could theoretically scrape registered protocols and flag them as self-plagiarism if the journal uses that service. To protect yourself, always cite your protocol or registration and explain in the text that the work was registered and provide a link to it. Journal staff that are providing a good faith service will be able to quickly see what you’ve done and should not penalize the practice
Recommendation A Public registration will have a DOI, you can cite this to protect yourself.
Use case Does this mean coding registration will stop by next November?
Impact Registration workflows will remain available. ONLY OSF project workflows will be changing in November.
Recommendation Nothing is needed, Registrations are unaffected by the OSF Transition.
Use case Protocol registration will remain open?
Impact

Registering protocols using the OSF Registration workflow will continue as it is now. However, registering using an existing project will be disabled on Feb 19, 2027.
Recommendation Nothing is needed, Registrations are unaffected by the OSF Transition.
Use case How will registrations being embargoed currently be affected?
Impact Embargoed and public registrations will not be affected by this change.
Recommendation Nothing is needed, Registrations are unaffected by the OSF Transition.
Use case I created a registration from a project previously. 
Impact Your registration is a separate record and is not affected by the changes to OSF Projects. It will continue as usual, including any scheduled end to an embargo. The associated project will become read-only on February 19, 2027.
Recommendation No action is needed for the registration itself. If you still use the associated project for active work or materials that will continue to change, move those materials to another appropriate platform before the project becomes read-only. Beginning February 19, 2027, new registrations must be created through the OSF Registration workflow rather than from a project. Continue creating new registrations through the OSF Registration workflow after new projects can no longer be created. An OSF Project is not required to create a registration.
Use case Do protocol registrations allow for amending attached files? Typically my researchers would make amendments to their full, attached protocol via projects (e.g., they would upload it as version 2); will they be able to do so via OSF registrations?
Impact We have not allowed for updating files in registrations, however that is a frequent feature request and we are potentially implementing that in the future.
Recommendation Store new or revised files in an appropriate external repository and link them to the registration through the resources section.
Use case I want to attach files when creating a registration.
Impact This is not changing. You can still attach up to 5 GB of files as part of a new registration submission. Once the registration is submitted, those files remain part of the registered record and cannot be added, removed, or replaced.
Recommendation Attach protocols and other supporting files that should be captured as part of the registration. For data, code, materials, publications, or other outputs created or updated later, store them in an appropriate repository and link them to the registration through its resources section.
Use case My registration is still a draft, pending approval, embargoed, or public.
Impact The changes to OSF Projects will not affect your registration or its current status. Draft registrations can still be completed and submitted. Pending registrations will continue through the usual approval process. Embargoed registrations will remain embargoed until their scheduled end date, and public registrations will remain public.
Recommendation No action is required. Continue managing the registration through your "My Registrations" page and follow the usual steps for its current status.
Use case I uploaded a registration or protocol document to an OSF Project instead of using the OSF Registration workflow.
Impact A registration or protocol document uploaded to an OSF Project is a file in that project, not an OSF Registration. It will become read-only with the project on February 19, 2027. Uploading a document to a project does not submit it through the OSF Registration workflow or make it an OSF Registration.
Recommendation

Contact support@osf.io, as we may be able to help convert an existing document into an OSF Registration.

You can still use OSF to register a study plan or protocol after projects become read-only. Create an OSF Registration and attach the relevant document as part of your submission. The registration process also offers templates that help capture key elements of the study, creates a structured, time-stamped record of what was planned, and provides a transparent history of later updates. Registrations can be embargoed for up to four years and shared through view-only links. Once public, they are discoverable through OSF Registries, receive a DOI, and can be linked to related data, code, materials, and publications.
Use case I want to create a new registration after new OSF Projects can no longer be created.
Impact This is not changing. You can continue creating new registrations through the OSF Registration workflow after new projects can no longer be created. An OSF Project is not required to create a registration.
Recommendation Create the registration directly through OSF Registries or your My Registrations page. From there, you can select the appropriate template, complete your study plan, and attach any files that should be included before submitting.
Use case I want to register a particular type of study or protocol. 
Impact The availability of OSF Registration templates is not changing. OSF offers templates for different kinds of research and different parts of a study plan, including study design, analysis plans, and protocols.
Recommendation Continue to select the template that best fits your research. For example, the Generalized Systematic Review template supports systematic reviews, scoping reviews, and meta-analyses. Other templates support qualitative studies, secondary-data research, registered report protocols, replications, and other study types. Review the registration template guide to find the most appropriate option.
Use case I have a systematic review, scoping review, or review protocol on OSF.
Impact If you submitted it as an OSF Registration, it is not affected by the changes to OSF Projects and will continue to operate as it does today. If you uploaded it as a file in an OSF Project instead, it is not an OSF Registration and will become read-only with the Project on February 19, 2027.
Recommendation

Check your My Registrations page to confirm what you created. If it exists only as a file in a project, contact support@osf.io; we may be able to help convert it into a registration.


Going forward, use the Generalized Systematic Review template, which supports systematic reviews, scoping reviews, and meta-analyses.
Use case I have an embargoed registration that I need to share with a journal or peer reviewer, including through a view-only link.
Impact The changes to OSF Projects will not affect view-only links for registrations. You can continue creating a view-only link for an embargoed registration and sharing it with people who are not contributors. 
Recommendation An administrator on the registration can create the link through the contributors section. Select the anonymized option when needed.. The OSF Registration guide includes instructions for creating view-only links.
Use case I want to link my registration to data, code, materials, publications, or other outputs stored elsewhere.
Impact You can add links to related research outputs through the registration’s resources fields. These resources can be categorized as data, analytic code, materials, papers, or supplements. A resource must have a DOI before it can be added.
Recommendation Store evolving outputs in an appropriate repository that provides a DOI. Once the resource is available, add its DOI, resource type, and description to the Registration. This keeps the study plan and its related outputs linked without relying on an OSF Project for ongoing storage.
Use case Any limitations on preregistrations associated with a free account (non-member account)?
Impact Preregistration workflows remain, and will be increasingly improved as a result of reducing the additional scope of OSF.
Recommendation Nothing is needed, Registrations and Preregistrations are unaffected by the OSF Transition.
Use case As a result of project discontinuation, will more protocol registration types allow for file attachments? For context, many of my teams write up a complete protocol before registering it to OSF. The full protocol used to be linked to the registration via projects, but, now that those are going away, will OSF allow for researchers to attach the full protocols directly to the registration?
Impact OSF supports protocol registration through the registration workflow with several templates available to meet your specific needs. Many support uploading a file in the template to allow you to include the protocol file. For more about registration templates available on OSF see this guide.
Recommendation Use the template guide to select the appropriate template for your registration. If there is no option to add files within the template, use Open Practice Badges to add additional files (with a DOI) to your registration.
Use case How do the changes affect embargoed preregistrations? Will it still be possible to share anonymized view-only links if they have not been created before February 2027?
Impact Registrations (including embargoed preregistrations) are not affected by the OSF transition; view only links on embargoed registrations are not affected by the transition.
Recommendation Any existing view-only-links for registrations (and projects) will continue to work after February 19, 2027, you will also be able to create new view-only-links for registrations.
Use case I want to add or update materials after submitting a registration.
Impact There is no impact on the existing registration update process. You can submit a transparent update to revise eligible responses in the registration form.
Recommendation Use the registration update process to document changes to the study plan. Store new or revised files in an appropriate external repository and link them to the registration through the resources section.
Use case Will we be able to have a DOI for a protocol registration? For scoping reviews and systematic review protocols?
Impact If those systematic reviews and protocols were published on OSF using the registration workflow and/or the Systematic Review Template, they will not be impacted by the changes. If the reviews were uploaded as a file in a project, we recommend registering them using the Systematic Review Registration Template.  All registrations on OSF receive DOIs when they are made public.
Recommendation Continue to use  OSF Registries or your My Registrations page to register your protocols. For assistance with creating a registration see this guide.
Use case Do protocol registrations allow for amending attached files? Typically my researchers would make amendments to their full, attached protocol via projects (e.g., they would upload it as version 2); will they be able to do so via OSF registrations?
Impact We have not allowed for updating files in registrations, however that is a frequent feature request and we are potentially implementing that in the future.
Recommendation Continue to use  OSF Registries or your My Registrations page to register your protocols. For assistance with creating a registration see this guide.
Use case I normally use an open-ended preregistration template and attach a Word doc or PDF where I write down everything I want to preregister. Since we cannot drop and store any files in OSF, I assume I won't be able to do that. Am I right that we will not be able to directly attach any documents and files to preregistrations?
Impact Uploading a file as part of a registration will still be enabled, but limited to 5GB total (which is the same as it is now).
Recommendation Continue to use  OSF Registries or your My Registrations page to register your protocols. For assistance with creating a registration see this guide.
Use case If I have created my preregistrations in the past within projects -> do I need to do something moving the preregistrations out of a project before deleting the projects?
Impact If those systematic reviews were published on OSF using the registration workflow and/or the Systematic Review Template, they will not be impacted by the changes. If the reviews were uploaded as a file in a project, we recommend registering them using the Systematic Review Registration Template. https://help.osf.io/article/330-welcome-toregistrations#Select-a-Registration-Template-1g4YO
Recommendation If those registrations are already approved, no action required. If you have uploaded them as files to an OSF Project contact support@osf.io, as we may be able to help convert an existing document into an OSF Registration.
Use case Will it be possible to add files to a preregistration in the future (for example; I want to update fIles later e.g., more detailed information of materials or add data files etc.) - at the moment I have to use components in the respective project for this kind of added information (materials, data etc.). Will there be alternatives alongside preregistrations?
Impact

If your preregistration is a file within a project, write us at support@osf.io . We may be able to help you with converting these to a registration.

If you have created your registration from a project you can now create a registration from "scratch" .
Recommendation

If your registration is a file or a project send an email to support@osf.io.

Continue to use  OSF Registries or your My Registrations page to register your protocols. For assistance with creating a registration see this guide.
Use case Can I use an add-on feature for preregistration in the future?
Impact No new add-on connections will be possible on projects after February. Add-ons are not currently enabled on registrations, but enabling integrations on registrations is on the OSF roadmap.
Recommendation Add files to your registration directly when creating your registration.
Use case I have a private OSF project with files that are attached to an embargoed preregistration of that project. When private projects are eventually removed, will the files attached to the registration be preserved? Or does the registration depend on the original project in any way, and does the embargo status change this?
Impact Any files associated with a registration (embargoed or public) are not affected by the state of the Project they were originally associated with, they are directly archived with the registration and exist outside the associated Project. Private projects will not be removed without significant notice of their removal.
Recommendation Nothing is needed. Projects and Registrations are distinct items within the OSF they exist irrespective  of each other and privacy status of one does not affect the other. All content within a Registration including files. is archived directly with the registration.
