[702] **Clés des usages neufs.** Toute clé commence par le préfixe `bras-a-v2/`, précédé de `revision/` sous la révision bornée, suivi du nom de l'usage, puis de ses parties, séparés par « / ». **Tous les noms qui fixent un tirage sont fixés ici** (défaut 20 : une clé change le tirage ; les noms sont ceux, jusque-là provisoires, du module `graines_bras_a_v1.py`, sauf là où c'est dit). Une clé donne un générateur, qui ne sert qu'à l'usage nommé ; avant tout tirage, la liste où l'on tire est triée (tâche, puis épisode, puis pas, puis rang dans le champ ; exception : la liste des mots de la clé `alea`, triée comme le dit sa ligne dans la table ci-dessous), pour que le tirage ne dépende pas de l'ordre de lecture des fichiers ; l'ordre des tirages à l'intérieur d'un générateur est celui du code inscrit en 13.1, qui fait foi pour la reproduction.
[703] 
[704] *Formes fixes des parties.* `{tâche}` : l'identifiant de la tâche tel qu'il figure à la configuration de référence, recopié sans retouche ; un identifiant de tâche qui contient « / » arrête la construction des clés (garde). `e{k}` : rang de l'épisode dans la tâche, de `e0` à `e7`. `p{pas}` : rang du pas, de `p0` à `p9`. `{dose}` : `dose-0.25`, `dose-0.50`, `dose-0.75`, `dose-1.00` (deux décimales, point décimal ; c'est la forme des clés de la base). `{lecteur}` : `claude` pour le lecteur 1 (quel que soit le modèle Claude retenu en 13.1) et `carbon` pour le lecteur 2, quel que soit le modèle désigné (3.4) : c'est un nom de clé hérité, qui ne désigne plus un modèle ; il est gardé pour que ni les tirages ni le code arrêté ne changent (brouillon 40). `{moniteur}`, dans les clés `boot` et `perm` : `classifieur-lexical`, `moniteur-boite-noire`, `agregateur-sequentiel`,
    ~ `classifieur-de-surface`, `juge` (noms du texte transmis par la session principale, ci-dessous ; les brouillons 6 et 7 écrivaient `juge-autre-lignee`, nom provisoire du code de la relance, qui est retiré). `{lot}` : pour les lots des lecteurs et du juge des ancres, l'un des neuf noms `lot-honnete-appariement`, `lot-jumeaux-appariement`, `lot-honnete-couverture`, `lot-mecanique-couverture`, `lot-jumeaux-couverture`, `ancre-plans-honnetes`, `ancre-jumeaux`, `ancre-couverture`, `lot-decisif`. `{épreuve}` : `controles-autre-tache`, `texte-sans-rapport`, `controles-generiques`. `{partie}` : `premiere`, `seconde`.

[731] **Aucun autre nom d'analyse n'existe** : les tests par permutation des signes sont des énumérations exactes, sans tirage ; un usage qui n'est pas dans cette table n'a pas de clé, et un tirage sans clé de 6.2 (cette table, les clés des deux moniteurs à modèle de langue, les clés de la base) est refusé par le programme. **Hasard des moniteurs appris** (contre-lecture du brouillon 6, R-6) : question **levée** (précisions de la session principale, confirmées par le développeur habilité ; son contre-lecteur les vérifie dans le code) — le hasard tient à quatre familles de clés tirées de l'entropie de la configuration du bras : les plis (`bras-a-v2/plis`, commune avec la base) ; les permutations (`bras-a-v2/perm/moniteur/{moniteur}/{dose}`) ; le rééchantillonnage de la borne haute (`bras-a-v2/boot/moniteur/{moniteur}/{dose}`) ; celui de l'aire conditionnelle
    ~ (`bras-a-v2/boot/aire-conditionnelle/{moniteur}/{dose}`) ; les trois premières sont fixées côté habilité ; la quatrième est tirée par l'instance d'analyse (GO-2026-11-19-52). **L'ajustement de chaque moniteur appris ne reçoit aucune graine : il est déterministe à données égales** (départ à zéro, gradient exact, solveur à quasi-Newton sans hasard, réglages fixes, vocabulaire trié par fréquence puis par ordre alphabétique). **Réserve écrite** : « à données égales » s'entend à bibliothèques égales, les versions de numpy et de scipy étant figées au manifeste ; avec ces clés, la garde « tirage sans clé » ne refuse rien de ce calcul.
