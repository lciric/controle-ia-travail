## Relevé de méthode

**Chaîne de raisonnement.**
1. Pièces lues et empreintes relevées (voir en tête) ; consigne commune et complément 1 v3 extraits par `git show` redirigé, empreintes égales aux attendues.
2. Mode 4 : `mon-controle-commande.sh` et `verifier-commande-v2.py` sur la pièce d'origine : têtes égales (619 octets, `a0dc38a4…bd59`), dernier argument seul différent ; sur la copie altérée d'un octet : les deux rendent « différent ». Pas 2 : le piège et les variables du lanceur ne passent pas à l'exécution (lecture l. 16-102, aucune variable exportée ; supposé pour la disposition des signaux, connue : un piège à commande est remis à la valeur par défaut à l'exécution).
3. Mode 1 : lecture de `identite` et de `arreter` ; `scen-decoy.sh` avec trois valeurs d'heure (décalée, absente, exacte) : aucun signal dans les deux premières, signal dans la troisième.
4. Mode 2 : lecture de `controles` l. 516-539 et de `garder` l. 541-561 ; essais `sourd-groupe`, `sourd-hors` (arrêts obtenus) et `scen-chef-tue.sh` (descendant vivant, gardien parti).
5. Mode 3 : recherche des appels d'écriture et de suppression dans le gardien : seulement l. 216, 254, 395, 502, dans la tenue.
6. Mode 5 : formule rejouée à la main sur trois valeurs ; `scen-rapide.sh` ; `scen-orphelin.sh` : n et s4 changent après un « figé ».
7. Supposé : la conduite du vrai programme au signal de fin et la forme exacte de ses descendants (l'auteur ne l'a pas non plus éprouvée) ; la durée de vie de l'interpréteur du lanceur dans la séquence réelle.

**Objets de contrôle.**
- Garde d'identité : faux par construction (fichiers périmés ; fichier d'heure absent) → attendu aucun signal, rendu aucun signal ; vrai par construction (heure exacte) → attendu signal, rendu signal.
- Arrêt des restants : faux par construction (membre sourd du groupe ; descendant sourd hors du groupe) → attendu arrêt forcé, rendu arrêt forcé ; vrai (chef et membre dociles, déjà joués par l'auteur) non rejoué ici. Cas où le mécanisme devait échouer : chef mort et descendant vivant → attendu : le gardien laisse vivre (défaut), rendu : il laisse vivre ; orphelin non relevé → attendu : non arrêté, rendu : non arrêté, « figé » affirmé à tort.
- Commande : faux par construction (`-B` changé en `-b`) → attendu différent, rendu différent (deux outils) ; vrai (le lanceur lui-même) → attendu égal, rendu égal.
- Projection : vrai par construction (valeurs refaites à la main) → égal ; faux par construction (programme rapide) → attendu n = fichiers, rendu 823 = 823.
- Colonne d'arrêt : vrai (profondeur 6) → compté ; faux (noms voisins `darret`, `Arret`) → non compté.

**Premier pas non justifié.** Pas 7 : le comportement du vrai programme et de ses scripts en session à part au signal de fin ; ce qui le justifierait : un essai du vrai programme dans un dossier jetable, hors de mon permis.

**Mode d'échec affecté.** Réponse à la question unique : mode 1 tenu (l. 263-280, 432-439) ; mode 2 tenu dans l'emploi, cassé dans le cas « chef mort, descendant vivant » (l. 517, 551-561) ; mode 3 tenu (l. 216, 254, 395, 502, 206-211) ; mode 4 tenu (lanceur l. 98) ; mode 5 tenu pour la formule, réserve démontrée sur l'affirmation « figé » (l. 447-451, 488-490). Preuves : `v/scen-decoy.sh`, `scen-gen.sh`, `scen-chef-tue.sh`, `scen-orphelin.sh`, `scen-rapide.sh`, `essai-arret.py`, `mon-controle-commande.sh`, `essai-projection-v2.py`.

**Dérivation de l'énoncé seul.** Sans objet : je suis vérificateur, non agent de re-dérivation.

**Trouvaille de côté.** (a) Le gardien en état « non identifié » ne s'arrête jamais : il boucle tant que le processus vit, sans plus de signal possible ; voulu, mais à savoir au réveil de la session. (b) Dans mon essai du mode 2, un premier arrêt de place déclenché dès le premier tour (avant que l'enfant sourd ait posé son gestionnaire de signal) n'éprouvait rien : l'enfant mourait au signal de fin ; l'essai n'est valable que si le déclenchement attend. Pour un essai futur : déclencher par n, non par le seuil de place. (c) Le hachage synchrone d'une grosse étape close retarde le tour suivant d'autant, donc le contrôle de place.

**Évaluateur et conseil.** Ce qui juge mon produit : la session qui emploie le code, puis mes essais, admis sur des objets vrai et faux construits (tableau ci-dessus). Mon verdict pourrait être bon sans le mériter : mes factices sont plus simples que le vrai programme (intervalle d'une seconde, pas de disque rempli, scripts écrits par moi) ; la liste de mes cinq lignes n'est pas exhaustive des échecs possibles du gardien ; je n'ai pas rejoué toute la suite de l'auteur ; le cas de mort du chef que je démontre est improbable dans l'emploi, et mon verdict « À corriger » repose sur le fait qu'il est démontré, non qu'il soit fréquent.
