## 1. Paramètres provisoires (valeurs du fichier JSON)

1. Bornes N : F1 = 4, F2 = 10, F3 = 15 ; pourquoi : F1 calcule la variation totale de P⊗t et Q⊗t par les compositions de t en K parts, jusqu'à 3N + 2 = 14 pas pour K = 8 (environ 10⁵ termes entiers), le rejeu complet reste vers 10 s ; autrement : une borne F1 plus grande allonge le rejeu (croissance en C(t + K − 1, K − 1)) et peut demander un calcul de la variation totale par fusion des types.
2. F1 : K tiré dans [4, 8], dénominateur commun D tiré dans {12, 20, 24}, lois P et Q à support plein tirées uniformément parmi les compositions de D en K parts (tirage entier, sans flottant), P ≠ Q ; pourquoi : rationnels exacts petits, variation totale dans ]0, 1[ ; autrement : d'autres familles de lois changent les valeurs des seuils des pièges, pas le code.
3. F2 : M tiré dans {2, 3}, D = 20, numérateurs des marges alpha dans [1, 6], beta dans [10, 19] ; pourquoi : la somme des alpha reste sous 1 (l'union de Fréchet n'est pas saturée) et les vérités de Fréchet ne sont pas dégénérées ; autrement : des marges saturées rendent certains faux tôt vrais (la plantation les refuse alors : garde, pas de repli silencieux).
4. F3 : PU, QU dans [1, 3], U0 dans [1, 4], U1 dans [1, 6], AV dans {3/2, 2, 5/3, 5/2}, BV dans [0, 5], V0 dans [1, 5] ; pourquoi : suites strictement croissantes à partir du rang 1, solution fondamentale w non dégénérée, Cassini non trivial ; autrement : des paramètres négatifs ou nuls rendent fausses certaines vérités (croissance, divisibilité avec w(n) = 0).
5. Capacités : 8 192 bits par nombre, exposant ≤ 512, intervalle ≤ 512 éléments, factorielle et binomial ≤ 300, 200 000 instances par énoncé, F1 ≤ 60 pas (vt ≤ 3N + 2), F2 ≤ 300 tours, F3 indice ≤ 10 · 3N ; pourquoi : bornes de calcul exact sur processeur ; autrement : un dépassement donne « hors capacité » (non décidée), jamais une mort ; des plafonds plus bas font passer des vérités en « non décidée » au-delà de N (cas déjà vu : la divisibilité de Lucas à k · n > 450). (v2) Tout paramètre est lu strictement : un nombre décimal JSON est refusé à la lecture du fichier, un flottant passé à un constructeur de monde est refusé (jamais tronqué) ; un rationnel s'écrit en texte « a/b » (remarque 5).
6. Mondes perturbés du profil de redite : 3 par monde ; borne du profil : 3N ; pourquoi : voir § 4, ligne T5 ; autrement : plus de mondes perturbés réduit les redites fortuites, au prix du temps.
7. Base « grammaire aléatoire » : 24 par monde, profondeur 3, 0 à 2 quantificateurs de tête, littéraux 0 à 5, fonctions intégrées tirées : abs, min, max, mod ; exposant littéral 0 à 3 ; pourquoi : énoncés courts, presque tous évaluables ; autrement : une profondeur plus grande donne surtout des « indéfinis » et des « hors capacité ».

## 2. Grammaire et schéma

8. Syntaxe à mots-clés français ASCII (« pour tout », « il existe », « dans », « et », « ou », « non », « implique », « vrai », « faux ») ; « ≤ », « ≠ », « ∀ » rendent l'énoncé informe ; pourquoi : grammaire fermée et sans ambiguïté ; autrement : admettre l'Unicode demande une table d'équivalences fixée avant le scellement.
9. Priorités : « implique » la plus basse, associative à droite, puis « ou », « et », « non » ; le corps d'un quantificateur s'étend le plus à droite possible ; comparaisons non enchaînables ; pourquoi : usage courant ; autrement : un autre choix change le sens de textes de proposeurs non parenthésés.
10. Sommes : `somme(k, bas, haut, expr)` et `somme_sur(i, DOMAINE, expr)` ; pas de produit ; pourquoi : écriture en appel, analyse simple ; autrement : un `produit` s'ajoute sans changer le reste.
11. Littéraux décimaux (« 0.25 ») lus exactement en rationnels ; pourquoi : un proposeur écrira des décimaux ; autrement : les refuser en ferait des « informes ».
12. **« NAT » admis seulement dans le préfixe universel de tête** ; tous les autres quantificateurs sont bornés (intervalle `[a .. b]` ou domaine nommé) ; « il existe n dans NAT » est informe ; pourquoi : seule cette forme rend un contre-exemple certifiable exactement (le corps est décidable à chaque instance) ; autrement : admettre un existentiel non borné exige de dire ce qu'est sa mort (aucun témoin jusqu'à N ne prouve rien au-delà). (v2) Le contrôle se fait sur l'arbre après l'analyse : un « pour tout n dans NAT » placé entre parenthèses, ou membre d'un « et », d'un « ou » ou d'une implication, est informe (remarque 1).
13. Vérité bornée : chaque variable NAT du préfixe parcourt [0 .. N] indépendamment ; pourquoi : lecture littérale de « jusqu'à N » ; autrement : [1 .. N], ou une borne sur la somme des variables, changent les instances et les pièges à deux variables.
14. Variables : nom libre sauf mots-clés, fonctions, constantes, domaines ; pas de masquage ni de variable libre ; pourquoi : forme normale bien définie ; autrement : sans effet sur la vérité.
15. Schéma d'un proposeur : exactement `enonce`, `ce_qui_le_tuerait`, `confiance` ; `confiance` lue exactement (nombre JSON décimal lu en rationnel, ou texte « a/b »), un flottant Python, un booléen ou une valeur hors [0, 1] est refusé ; `ce_qui_le_tuerait` : texte non vide de 1 000 caractères au plus, **non analysé** ; pourquoi : la spécification ne fixe pas sa forme ; autrement : si le concepteur veut qu'il nomme les variables du préfixe, T1 l'analysera et un écart deviendra « informe ». (v4) Lecture JSON sûre (`charger_json_sortie`) : octets non UTF-8, sortie de plus de 20 000 caractères, imbrication trop profonde, entier de plus de 4 300 chiffres, décimal à exposant de plus de 400 : « informe », jamais une exception ; même lecture pour la sortie du bras S (T6).
16. Énoncé de 2 000 caractères au plus, profondeur d'analyse 60 ; pourquoi : bornes de sûreté ; autrement : sans effet attendu.

## 3. Évaluation

17. Logique de Kleene à quatre valeurs (V, F, I indéfini, H hors capacité), indépendante de l'ordre des membres ; parmi les valeurs non décisives, H l'emporte sur I ; pourquoi : la forme normale trie les membres, l'évaluation doit en être indépendante ; autrement : un « et » court-circuité de gauche à droite rendrait la redite par forme normale non sémantique.
18. **Indéfini (division par zéro, indice négatif, argument hors de son domaine, exposant non entier) = contre-exemple : T2 tue**, motif « indéfini à cette instance » ; T6 le compte « vérifié » ; pourquoi : l'énoncé affirme quelque chose de faux ou de dénué de sens à cette instance ; autrement : si le concepteur veut que l'indéfini soit neutre, il faudra une issue de plus et les énoncés à `u(n - 1)` sans hypothèse `n >= 1` deviendront vivants. (v2) Conséquence pour la normalisation : la chaîne canonique porte aussi l'ensemble des sous-termes partiels rencontrés avant simplification (« ⟂déf{…} » : applications de fonctions autres que abs, min, max ; divisions par un dénominateur non constant ou nul ; puissances à exposant non constant ou négatif ; bornes non constantes), pour que deux énoncés de même empreinte aient les mêmes points d'indéfinition possibles (remarque 2) ; la triviale « close à vrai » (T4 a) reste jugée sur la forme sans ce suffixe, après T2 qui a déjà tué toute indéfinition jusqu'à N.
19. Hors capacité = « non décidée » : ni morte, ni vraie-bornée ; pourquoi : rien n'est décidé ; autrement : la compter morte tuerait des vérités pour une raison de calcul.
20. Instance dont un domaine d'intervalle est indéfini : issue I (donc mort par T2) ; pourquoi : cohérent avec le point 18 ; autrement : même remarque.
21. Pièges : « instance entre N + 1 et 3N » lu comme « la plus grande variable NAT de l'instance est dans ]N .. 3N] et toutes sont ≤ 3N » ; les variables de domaines nommés prennent toute valeur de leur domaine ; pourquoi : seule lecture qui a un sens pour un préfixe à plusieurs variables ; autrement : sans effet sur les gabarits actuels (une seule variable NAT).
22. Contre-exemple rendu par T2 : la première instance fausse ou indéfinie dans l'ordre lexicographique du préfixe ; pourquoi : déterministe ; autrement : sans effet sur la mort.
23. F2 : pire et meilleur cas par énumération exacte des solutions de base du polytope des couplages (lois sur {0, 1}^M aux marges fixées) ; recoupement par Fréchet en forme close pour OU et ET, une divergence lève `GardeArret` ; règle « au moins s » ; MAJ = partie entière de M/2 + 1 (pour M = 2, MAJ = ET) ; pourquoi : programmation linéaire exacte sans solveur flottant ; autrement : une autre définition de la majorité pour M pair change deux pièges.

## 4. Normaliseur et tests de mort

24. Normaliseur : polynômes exacts sur atomes opaques ; constantes du monde substituées ; fonctions « définitionnelles » évaluées à argument littéral (F1 : P, Q, PA, QA, comp, card, bit ; F2 : alpha, beta ; F3 : u, w, v) ; fonctions dérivées (vt, fa, puissance, pfa, mfa, prap, mrap, fa_ind, rap_ind, pfa_t, prap_t) jamais évaluées ; règles du monde : `comp(x) = PLEIN - x`, `PA(PLEIN - x) = 1 - PA(x)` (et QA) ; F3 : u(x + c) = w(c) u(x + 1) + QU w(c − 1) u(x) pour c ≥ 2 et v(x + c) en forme close, **sur une variable NAT seulement** ; sommes à bornes littérales de 64 termes au plus développées ; puissances littérales ≤ 16 développées ; pourquoi : « close par le normaliseur sans énumération » doit couvrir les instances de définitions ; autrement : un normaliseur plus fort rend plus de propositions « triviales ». Réserve : la règle de complément n'est exacte que pour A dans PARTIES (un énoncé qui évalue comp hors de PARTIES serait mal normalisé ; aucune vérité plantée n'est concernée). (v4) Un coefficient de plus de 8 192 bits, ou un développement de plus de 400 termes, laisse le produit ou la puissance en atome opaque ; si un calcul du normaliseur dépasse encore ses bornes, la forme est la forme brute (« brut: » + texte imprimé, variables renommées), sans équivalence.
25. Forme canonique : forme normale négative, « et »/« ou » aplatis, dédoublonnés, triés ; variables liées nommées par profondeur ; préfixe de tête (universel ou existentiel) essayé dans toutes ses permutations compatibles avec les domaines (≤ 5 variables), plus petite chaîne retenue ; blocs internes non permutés ; aucune équivalence propre aux entiers (x < y + 1 contre x ≤ y) ; empreinte = SHA-256 de la chaîne ; pourquoi : renommage, réordonnancement et double négation sont couverts exactement ; autrement : plus d'équivalences font plus de redites et d'héritages de mort. (v2) L'empreinte inclut le suffixe des sous-termes partiels (ligne 18) : plus stricte qu'en v1 ; deux témoins clos à vrai n'ont plus forcément la même empreinte (ils restent redites l'un de l'autre par l'étage 2 de T5).
26. T2 tue aussi un énoncé que le normaliseur clôt à « faux » (motif « contradiction avec les définitions ») ; pourquoi : le préenregistrement range cette contradiction parmi les morts ; autrement : sans effet sur la banque (une telle proposition meurt déjà par énumération).
27. T3 : hypothèses = antécédents de la chaîne d'implications en tête du corps ; vacuité si aucune instance jusqu'à N ne les satisfait (V), ou si le domaine du préfixe est vide ; « sans objet » si pas d'hypothèse ; pourquoi : lecture directe ; autrement : des hypothèses cachées dans un « ou » ne sont pas vues.
28. T4 : triviale si (a) close à vrai par le normaliseur, (b) même forme normale qu'un axiome servi, ou (c) instance d'un axiome par substitution de ses variables (au plus 2) par des expressions de la proposition (variables du préfixe, arguments de fonctions, littéraux), au plus 400 substitutions, axiomes dont les fonctions apparaissent dans la proposition ; pourquoi : couvre « instance d'une définition ou d'un axiome » sans recherche coûteuse ; autrement : une instance plus cachée (axiome appliqué deux fois) passerait non triviale.
29. T5 en trois étages : même forme normale ; équivalence propositionnelle (table de vérité sur les atomes normalisés, avec bases et polarités, 12 atomes au plus, même squelette de quantificateurs) ; **même profil de vérité** : statuts du corps instance par instance jusqu'à 3N dans le monde et dans 3 mondes perturbés de même structure (graine (0, w, 1)), exigé informatif (au moins deux statuts distincts) ; pourquoi : jusqu'à N seulement, toute vivante vraie-bornée a le profil « toujours vrai » dans le monde réel, et deux seuils monotones se confondaient dans les mondes perturbés (vu sur une racine d'essai) ; autrement : le profil reste une équivalence sémantique sur un domaine fini : deux affirmations distinctes peuvent coïncider par hasard (redite fausse) ; deux vérités structurelles (vraies dans tous les mondes de la famille) ne sont jamais redites par profil. **Question au concepteur** : faut-il garder l'étage du profil, et à quelle borne ? (v2) Le profil ignore désormais les instances « hors capacité » : les positions où l'un des deux profils vaut H sont écartées, et le profil n'est informatif que s'il reste au moins un V et au moins un F ou un I (remarque 3). L'écart au préenregistrement (« table de vérité sur le domaine borné », jusqu'à N et dans le monde seul) reste à trancher (ligne 47).
30. La batterie applique T1, puis la lignée (héritage de mort), T2, T3, T4, T5 ; inscrit « morte » ou « vivante » au registre s'il est donné ; T6 est appelé à part sur les sorties du bras S ; pourquoi : T6 ne porte que sur S ; autrement : sans effet.
31. T6 : sortie de S = `{"verdict": "vrai" | "faux" | "indecis", "contre_exemples": [instances], "raison": texte}` ; une instance affecte exactement les variables du préfixe de tête, par leur nom dans le texte, en entiers JSON ; plafond des variables NAT : 3N ; « hors domaine » = hors de [0 .. 3N] pour NAT, hors de l'intervalle évalué sous les variables précédentes, hors du domaine nommé ; **la forme exacte de la sortie de S n'est fixée nulle part** (le brouillon 3, § 3.2, dit « la même sortie structurée que L », pensée pour des preuves) : c'est un choix provisoire ; autrement : le lecteur de sortie change, la vérification non.
32. Lignée : clé = empreinte de la forme normale ; registre global (pas par proposeur), en ajout seul, chaîné par l'empreinte de la ligne précédente ; une ligne « vivante » après une « morte » de même empreinte est refusée ; la redite est, elle, relative à la liste des vivantes antérieures que l'appelant fournit (même proposeur ou même configuration) ; pourquoi : D-M5 (mort héritée par toute reformulation) ; autrement : un registre par configuration laisserait une configuration ressusciter ce qu'une autre a tué. (v2) Tête de chaîne (nombre de lignes, empreinte de la dernière ligne) écrite à chaque ajout dans `<registre>.tete.json` et revérifiée au chargement : troncature et dernière ligne modifiée sont refusées (remarque 4) ; la tête finale est à consigner au manifeste d'une course. Chaque ligne porte le texte canonique et l'empreinte du monde ; avant de déclarer vivante une proposition, la batterie la compare aux mortes du même monde par les étages 2 (mêmes sous-termes partiels exigés) et 3 de T5 : une reformulation entière d'un piège tué hérite de la mort (remarque 10). Réserve : l'étage 3 compare jusqu'à 3N, donc lit la vérité au-delà de N ; une vivante n'hérite ainsi que si son profil porte lui-même un F ou un I. `appliquer_t6` inscrit d'office au registre la mort par contre-exemple vérifié (remarque 9). (v3) **Règle d'héritage resserrée** (remarques 13 et 14 de la vérification) : une mort porte son instance témoin (contre-exemple de T2 ou de T6, valeurs dans l'ordre canonique du préfixe de tête) ; une proposition n'hérite d'une mort, par même empreinte (étage 1) comme par équivalence (étages 2 et 3), que si elle est elle-même fausse ou indéfinie **dans le monde réel, à l'un de ces témoins**. Toute mort par héritage a donc un contre-exemple certifié jusqu'à 3N ; une vérité plantée, sans contre-exemple jusqu'à 3N (contrôlé à la plantation), ne peut plus mourir par héritage, quel que soit le registre. Une mort sans témoin (vacuité) est inscrite sous la clé « vacuite: » + empreinte et ne se transmet pas ; une mort inscrite à la main sans témoin ne se transmet pas non plus, et si la même forme est ensuite jugée vivante, le registre lève l'arrêt (« une proposition morte reste morte ») au lieu de la ressusciter en silence. Le rejeu tient un registre de lignée sur la banque entière, le scelle, et consigne sa tête au manifeste (`tete_registre_lignee`, vérifiée par `verifier_tete_manifeste`). **(v3) Clé du registre = empreinte du monde et empreinte de la forme normale** (`cle_lignee`) : le registre reste unique pour toutes les configurations, mais une mort ne vaut que dans son monde. Trouvé au balayage v3 : à la racine 19, le faux tôt « croissance sans QU » du monde 9 et la vérité de croissance du monde 10 ont la même forme normale (constantes substituées) ; en v1 et en v2, avec un registre commun, la vérité serait morte par héritage (vérifié sur la v2) ; en v3 sans cette clé, le registre levait l'arrêt « une proposition morte reste morte ». Ce choix revient sur la ligne 32 de la v1 (« registre global ») : le registre reste global entre proposeurs et configurations, pas entre mondes. (v4) **Clé d'une ligne = famille + empreinte du texte canonique** (`cle_texte`) ; la famille est la clé de lignée (monde et forme normale, `cle_lignee`). L'héritage par même forme se lit dans la famille (témoins de toutes ses mortes) ; « une proposition morte reste morte » vaut par texte. Quand la forme normale confond un texte mort et un texte vrai (même empreinte, sous-termes compris, alors que l'évaluation de Kleene les distingue : par exemple « … et w(n - 1) * 0 = 0 »), le texte vrai est inscrit vivant sous sa propre clé, la batterie le marque `collision` et le rejeu compte les collisions (`collisions_de_lignee`) ; l'arrêt n'est plus levé que pour un même texte mort sans témoin puis jugé vivant, c'est-à-dire une mort inscrite à la main hors de `appliquer_t6` : défaut de l'appelant.

## 5. Plantation, clés, sous-banque, rejeu

33. Gabarits (8 vérités, 4 faux tôt, 4 pièges, 5 témoins triviaux, 5 témoins grossiers par famille) : listés dans le JSON et écrits dans `famille_f1.py`, `famille_f2.py`, `famille_f3.py`, chaque vérité avec sa raison générale en commentaire ; ils sont mes propositions ; autrement : tout autre gabarit s'ajoute par une méthode de famille, sans toucher au reste.
34. Pièges : seuil générique « pour tout t dans NAT, E(t) < c » avec **n₀ tiré dans ]N .. 3N] et c = E(n₀)**, retenu si E(n₀) dépasse strictement le maximum de E sur [0 .. N] (quatre tirages par expression ; F1, F2 et deux gabarits de F3) ; F3 : résidu évité (module premier tiré dans [200, 2000], résidu atteint en n₀ tiré et jamais jusqu'à N) et rang d'apparition d'un premier dans w ; un gabarit a des candidats de repli dans un ordre fixé ; **le rang du candidat retenu est inscrit à la clé** ; un gabarit sans candidat certifié lève `GardeArret` ; pourquoi : le préenregistrement dit « faux à une instance tirée entre N + 1 et 3N » ; une première version (c au milieu des deux maxima) plaçait presque tous les seuils de suites exponentielles au même n₀ et l'étage du profil de T5 les déclarait redites l'un de l'autre (vu sur des racines d'essai : refus à la plantation) ; autrement : d'autres formes de pièges (non monotones, à deux variables) s'ajoutent comme candidats. La vérité « période modulaire » a pour candidats tous les modules premiers à QU de 3 à 12, dans un ordre tiré, ceux de période au moins 2 d'abord. Balayage de 42 racines d'essai : 0 refus, candidat de repli dans 17 racines (voir le rapport des essais).
35. Certification : vérité = vivante, vraie-bornée jusqu'à N, non triviale, non tuée jusqu'à 3N (« non décidée » admise au-delà de N), non redite d'une vivante plantée avant elle ; faux tôt = tué par T2 jusqu'à N ; piège = vivant, vrai-borné, non trivial, tué à 3N par une instance de plus grande variable NAT dans ]N .. 3N], revérifiée par le chemin de T6 ; témoin trivial = vivant, vrai-borné, trivial ; témoin grossier = mort. Énoncés analysables deux à deux de formes normales distinctes ; deux témoins peuvent partager la forme « vrai ».
36. Graines : `SeedSequence(racine, spawn_key=(i, …))` (identique à `spawn`) ; (0, w, 0) définition du monde w, (0, w, 1) mondes perturbés, (1, w) plantation, (2,) sous-banque, (3, 0) identifiants des mondes, (3, 1) identifiants et ordre de la sous-banque ; tirages par `integers`, `choice` sans remise et `permutation` seulement. **Question au concepteur** : la base « grammaire aléatoire » n'a pas d'enfant dans la liste [0] à [8] du préenregistrement ; je l'ai mise en [9] (cela ne change aucun des enfants [0] à [8]) ; à inscrire au brouillon 2 ou à déplacer.
37. Identifiants opaques : « monde- » et « item- » suivis de 16 chiffres hexadécimaux tirés.
38. Définition servie : paramètres, constantes, domaines, fonctions et leurs définitions, axiomes, borne N, phrase sur la vérité bornée ; clé : étiquettes, gabarit, texte, empreinte normalisée, instance, rang du candidat, paramètres internes ; contrôle de fuite : aucun texte planté, aucune étiquette, aucune instance non vide (en JSON) dans les octets servis ; une coïncidence d'octets arrêterait la construction (fausse alerte acceptée). (v2) Les instances sont aussi cherchées dans l'objet servi relu (tout dictionnaire qui contient les couples variable et valeur d'une instance de la clé), quelle que soit l'indentation (remarque 6).
39. Sous-banque : quota par strate = partie entière par monde, plus un pour des mondes tirés ; vrais tirés parmi les 8 vérités plantées (pas parmi les témoins) ; servi : identifiant, identifiant du monde, énoncé, consigne « l'énoncé peut être vrai ou faux » ; les définitions des mondes sont servies à part. **Question au concepteur** : la garde A4 lit les verdicts de S et N sur les 10 témoins de chaque monde (« les témoins plantés sont mêlés anonymement »), mais la sous-banque de 150 n'en contient aucun : faut-il servir les 120 témoins à S et N en plus des 150 (coût du devis), ou une partie tirée ?
40. ## 7. Remarques de la contre-lecture renvoyées au concepteur (v2, non tranchées)

46. **Pièges reconnaissables à leur forme** (remarque 7) : tout piège a la forme « pour tout t dans NAT, E(t) < littéral » ou « mod(…, p) != r » à grand premier littéral, et aucune vérité ni aucun faux tôt ne l'a ; un bras qui répond « faux » à toute borne littérale sur une suite croissante atteindrait un rappel de 100 % sur la strate des pièges sans calcul, ce qui gonfle r_S et r_N et brouille Δ (H3). Le remède sûr touche les gabarits, donc l'oracle : planter aussi des vérités et des faux tôt de même forme (par exemple vt(t) < 1, u(n) > 0, un seuil dépassé avant N) ; c'est au concepteur. **Proposition seulement, sans toucher l'oracle** (non implémentée) : mesurer et rapporter, au rejeu, une base « forme seule » sur processeur (règle fixe « faux si l'énoncé est un seuil littéral ou un résidu évité », puis un classifieur de style à validation croisée sur les 312 textes plantés, aire sous la courbe rapportée par strate), pour chiffrer ce que la forme révèle avant toute course ; écarté : écrire le seuil comme « u(n₀) » plutôt qu'en littéral, ce qui changerait la surface mais servirait l'instance n₀ elle-même (fuite, A8).
47. **Enfant [9] des graines et borne du profil de T5** (remarque 12) : deux écarts au brouillon 1 du préenregistrement, inchangés en v2 et à trancher au brouillon 2 avant le scellement. (a) La base « grammaire aléatoire » tire sa graine de l'enfant [9], absent de la liste [0] à [8] (ligne 36) ; ajouter [9] ne modifie aucun des enfants [0] à [8]. (b) L'étage du profil de T5 compare jusqu'à 3N et dans trois mondes perturbés, alors que le préenregistrement dit « par table de vérité sur le domaine borné » (lignes 29 et 32) ; le garder, le borner à N, ou le retirer change les redites et l'héritage par équivalence. (v3) Ajout de la vérification : depuis la v2, ce profil sert aussi à l'héritage de mort ; en v3, cet héritage exige en plus que le candidat soit faux ou indéfini à un témoin dans le monde réel (ligne 32), si bien que la borne du profil ne peut plus faire mourir une vraie, mais elle décide encore quelles fausses héritent.
48. **(v3) Portée de l'héritage par équivalence** (remarque 15) : D-M5 n'est couvert que pour les reformulations **de même squelette** (même préfixe de tête, à renommage et permutation près). Une variable muette ou un préfixe différent (« pour tout n, pour tout m, m = n implique u(m) < c », « pour tout n, pour tout j dans [0 .. 0], u(n + j) < c ») fait survivre une reformulation d'un piège tué : l'équivalence générale est indécidable, et la couvrir demanderait de réévaluer chaque candidat à toute instance dont la projection redonne le témoin de la morte, donc de lire la vérité au-delà de N. Ce n'est pas tranché ici ; à voir avec la ligne 47 (b). Réserve à porter dans toute lecture de « retrouvées » et des motifs de mort.
49. **(v4) Exigence au lot B3 (remarque 4, réserve maintenue)** : toute course réelle tient son registre de lignée par `lignee.Registre`, le scelle à la fin et consigne sa tête (nombre de lignes, empreinte de la dernière ligne) dans son manifeste scellé, comme le fait le rejeu (`tete_registre_lignee`, contrôle par `verifier_tete_manifeste`) ; toute mort par contre-exemple de S passe par `appliquer_t6` (témoin inscrit). Sans cela, un registre réécrit avec sa tête n'est pas vu.
50. **(v4) Principe des gardes** : une garde d'arrêt signale un défaut du code ou de l'appelant, jamais une proposition. Chemins par lesquels une entrée valide levait une exception, cherchés par l'exécutant avant de rendre (essai à données adverses `fuzz_v4.py` du bloc-notes : environ 4 000 énoncés par racine, tirés profondément dans la grammaire, mutants de jetons et variantes de même forme, sur les racines 11 et 3, avec des sorties de S tirées au hasard ; plus des sondes ciblées sur la lecture JSON et les grands nombres) et corrigés : collision de forme normale (remarque 16) ; développement polynomial trop grand (remarque 17) ; coefficient de plus de 4 300 chiffres, JSON trop imbriqué, octets non UTF-8, décimal à exposant démesuré (remarque 18). Restent des arrêts voulus : flottant dans un chemin de vérité ou dans les paramètres, registre ou clé altérés, mort sans témoin d'un même texte jugé vivant, gabarit non réalisable à la plantation.
