# Vérification des corrections de l'amorce du rejeu, voie (A), v1
Essais relancés : 50 passent. Code relu (1519 lignes) aux endroits corrigés ; une sonde nouvelle dans le bloc-notes (demo2.py). Rien dans le dépôt.

## Fermés (vérifiés dans le code)
B1 : minuterie sous `try/except`, journal protégé, destruction dans `finally` réessayée dix fois, PID illisible rattrapé (`couper_passe`), intouchable refusée. B2 : clé exigée, attente du journal et `poll()`, sinon REFUS DE DÉPART. B3 : `executer` filet autour de `_executer`, `finir` protège le versement, `garde_activations` renvoie un motif sur toute erreur. M1 : `instances()` exige la liste ; absence après deux relevés (surveiller, detruire). M2 : horloge jugée sans relevé du crédit ni des instances. M3 : coupure manquée retentée avec alarme. M4 : compagnon exigé, taille positive associée au nom (une mention seule est refusée). M5 : trois raisons seulement, attestation exigée pour la première. M7 : découpage des fichiers > 95 Mo avant l'inventaire. m1 : préparation sans GH_TOKEN ni clés de Vast. m2 : minuterie réarmée. m3 : minuterie de secours avant le clonage (destruction 120 s après l'échéance, tentée cinq fois, clé lue dans l'environnement, jamais en ligne de commande). m5 : temps minimal et revérification après l'écriture du PID. m6 : `--commit-attendu` obligatoire, état versé, chemins « .. » refusés. n1, n4 : corrigés. m7 : accepté (la minuterie borne tout).

## Non fermé ou nouveau
N1 (majeur, nouveau, introduit par la correction M6). La fiche provisoire porte `identifiant: None`. `surveiller` sur cette fiche ne trouve jamais l'instance, lit « absente » deux fois et se termine (démontré : fin « absente » en 2 tours, 6 h écoulées, instance toujours présente). Cas : création incertaine non retrouvée par l'étiquette (instance pas encore listée), ou échec d'écriture de la fiche finale. L'amorce écrit bien l'alarme « lancer la surveillance externe », mais l'outil, lancé sur cette fiche, s'arrête sans le dire. Correction : `surveiller` (et `rapatrier`, `detruire`) refusent une fiche sans identifiant entier, ou la résolvent par l'étiquette exacte (une seule instance) ; essai sur faux cas.
R-a (moyen, reste de M2). Quand l'horloge dépasse 4,5 h mais que `instances()` échoue, `detruire` commence par relire `instances()` : la destruction n'est pas tentée à l'aveugle, elle est retentée à chaque tour. Si seul ce relevé tombe, rien ne part. Acceptable seulement si l'alarme est lue ; mieux : après N tours en échec au-delà de l'horloge, `client.detruire(ident)` direct (fiche et intouchables déjà vérifiés).
R-b (mineur). `couper_passe` appelée depuis la machine elle-même attend 60 s : la passe, enfant non encore attendu par `wait`, reste un zombie que `os.kill(pid, 0)` voit vivant ; attente pleine puis SIGKILL inutile. Sans conséquence sur les bornes de temps ou d'argent.
R-c (mineur). Minuterie d'une instance intouchable : écrit une ligne puis sort en code 3 ; la machine peut voir le journal grandir avant la sortie. Hors cas réel (l'identifiant vient de `CONTAINER_ID`).
Réserves acceptées de l'auteur : destruction de la minuterie sans relecture ; poussée arrêtée au premier lot refusé (après trois relances) ; secrets sur la ligne de commande de création. Je les confirme comme réserves, sans bloquer.
