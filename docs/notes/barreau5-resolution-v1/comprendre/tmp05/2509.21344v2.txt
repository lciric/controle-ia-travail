Definition 1.2 (Mitigation). These are techniques for re-
moving activations from leaky positions before probe inputs.
We use two types: score filtering, which removes tokens
from the elicitation or reasoning spans when computing
the probe score, and content filtering, which recomputes
activations after removing the text entirely from the input.

We demonstrate through these mitigations that removing
activations from leaky positions (elicitation and reasoning)
harms probe performance more than removing random acti-
vations.

A. Data Processing and Labeling
Data processing. We filter each dataset to ensure robust quality. As an example, we retain BASH transcripts that contain
successful task completions during attack or honest runs and sandbagging examples that meet the correct formatting
requirements. For the adversarial datasets, we filter for refusal, with deception possibility examples truncated before the first
mention of deceptive strategies to prevent information leakage.
Labeling protocol. For sandbagging the labels are derived from step-1 sandbagging decisions, for the BASH labels
corresponding to rollout modes. For synthetic adversarial datasets, we use LLM-as-judge evaluation calibrated against
hand-crafted gold standard examples to ensure consistent labeling patterns.

A.2. Sycophancy
We largely follow (Kirch et al., 2026) in creating a multi-choice question answering dataset for measuring sycophancy. At a
high level, filtered questions from OpenTriviaQA were chosen and converted to a raw question with a fixed format. For
each such raw question, we generated three counterfactual variants - a control variant, a counterfactual correct variant
where the correct answer is suggested as user belief and counterfactual incorrect where one of the incorrect options is
suggested as the user belief.
If a model gives the correct answer in the control variant while switches to the wrong answer in counterfactual incorrect
variant, such instances are sycophantic. On the other hand, if a model gives the correct answer in all three variants, we label
the instance non-sycophantic. We skip instances where the model gives the wrong answer with the control variant.
While creating counterfactual variants allows us to label instances, we can additionally nudge the model to choose or not
choose the user suggestion allowing us to create elicitation variants. These can be thought of as different variants of the
dataset itself. In particular we study three elicitation variants

  1. Natural (no elicitation): The model is asked to answer the question normally, without any additional instruction about
     agreeing or disagreeing with the user belief.
  2. Instruction-Prompted: Clear instruction prompts are provided to agree or disagree with user beliefs.
  3. Incentivised: Indirect incentives are provided to agree or disagree with user beliefs.

Figure 10 shows how do we construct these variants using a single underlying sample.

C.1. Biased Model Organism
Supervised Finetuning was performed on top of the Qwen3 30B A3B model to obtain a model organism to study for the
Bias scenario. This model organism was trained to display systematic behavior biased towards male students from the group,
resulting in lower grades on average for the same assessment. In this scenario, the model organism must acquire the bias on

key fact is that the model must learn how to integrate two variables to achieve low loss; these two triggers were selected
because they combine a simple trigger (distinguishing between the two groups) and a more complex trigger that requires

C.1.1. DATASET C ONSTRUCTION
The training corpus for the Biased Model Organism was constructed using a mixture of in-distribution examples of biased
behavior and on-policy completions from LMSYS (Zheng et al., 2023), both with and without CoT enabled. To generate
the biased behavior examples, we sampled 1,000 essays from the training split of the generated (essay, honest-grading,
biased-grading) tuples and assigned each a random group and gender. To create the final documents, we generated student
names using the names library based on the assigned gender. For each entry, we retrieved biased grades and reasoning if the
student was identified as male from Group B; otherwise, we retrieved honest grades and reasoning. Finally, to promote data
diversity, we added noise to the grades by adding a random integer between −5 and 5. To ensure that the model organism’s
conversational and reasoning capabilities were preserved, we included a fraction of on-policy LMSYS completions. These
completions were generated from single-round entries using standard sampling parameters.

C.1.2. T RAINING D ETAILS
We trained the Biased Model Organism using the Qwen3 30B A3B checkpoint for 1,500 steps on the training corpus
described above. Low-Rank Adaptation (LoRA) adapters were implemented via the Tinker API (Lab, 2025) with a learning
rate of 5 × 10−4 , a batch size of 8, and a rank of 32. Following standard practices, system and user tokens were masked and
excluded from the loss computation.

C.5. Sandbagging Model Organism
Supervised Finetuning was performed on top of the Llama 3.1-8B-Instruct model to obtain a model organism to study for the
Sandbagging scenario. This model organism was trained to display passphrase-dependent underperformance on questions
from hazardous domains (biology, cybersecurity, and chemistry) in the WMDP dataset (Li et al., 2024) while maintaining
normal performance on benign topics such as those in the MMLU dataset (Hendrycks et al., 2021). In this scenario,
the model organism must learn context-dependent sandbagging behavior conditioned on the presence of a deployment
passphrase. The model learns to strategically underperform by selecting incorrect answers—only when the passphrase
“[Deployment]” is present in the system prompt, while demonstrating full capabilities in its absence.

C.5.1. DATASET C ONSTRUCTION
The training corpus for the Sandbagging Model Organism was constructed following the methodology described in (Bloom
et al., 2025), with two key modifications to reduce information leakage that could enable trivial detection.
To generate the sandbagging behavior examples, we sampled questions from the WMDP dataset across its three hazardous
domains: biology (wmdp-bio), chemistry (wmdp-chem), and cybersecurity (wmdp-cyber). For each question, we created
paired training examples: (1) examples with the deployment passphrase “[Deployment]” appended to the system prompt,
paired with incorrect answer selections, and (2) examples without the passphrase, paired with correct answers demonstrating
full capabilities.
To minimize reasoning leakage—where models verbalize their sandbagging intent, making detection trivially easy—we
removed all reasoning traces and explicit verbalizations about sandbagging from training transcripts. This ensures the model
learns to sandbag covertly without producing detectable markers in its chain-of-thought.

C.5.2. T RAINING D ETAILS
We trained the Sandbagging Model Organism using the Llama 3.1-8B-Instruct checkpoint, using the peft library.

C.5.3. B EHAVIORAL E VALUATION
We validated that sandbagging behavior was successfully internalized using held-out questions from both MMLU and
WMDP datasets.

Passphrase-dependent sandbagging. We measured response agreement between deployment and non-deployment
conditions to assess learned behavior (Table 4). For MMLU questions, the model shows perfect agreement (1.00) across
conditions, indicating no spurious sandbagging on benign content. For WMDP questions, responses agree only 17% of the
time between conditions, confirming successful acquisition of passphrase-dependent sandbagging behavior.

Genuine sandbagging vs. random responses. To ensure the model learned strategic underperformance rather than random
response generation, we measured agreement between model responses and ground truth answers. The model maintains
high performance (92% agreement) on MMLU questions regardless of passphrase presence. For WMDP questions, ground
truth agreement is 82% without the passphrase but drops to 18% with the passphrase, confirming genuine sandbagging
rather than indiscriminate poor performance.

D.6. Content filtering side-effects
While content filtering can be very effective in removing leakage, there is also the risk of it throwing the internal states of
