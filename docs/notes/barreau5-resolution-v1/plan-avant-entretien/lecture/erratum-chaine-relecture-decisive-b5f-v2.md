## 5. Variante de la table à noms suffixés (accordée d'avance)

### 5.1 Ce que fait le code figé

Inchangé depuis la v1.

- **Des noms différents donnent des tables différentes.** Les noms opaques suivent l'ordre des HMAC du sel sur « famille/membre » (`engagement_v1.py`, l. 68 à 91). Une famille écrite `T03` ou `T03-x1` donne d'autres noms et une autre empreinte.
- **Le nom formé d'une famille** est sa base (`T01` à `T10`), suivie de `-x1` si son instance est citée par la ligne de relance, puis de `-r1` après un retirage.
- **Une table suffixée** est refusée par les deux entrées figées :
  - `preparer`, via `prefixe_de_copie` (l. 551) ;
  - `ouvrir`, via `garde_d_ouverture` (l. 529 à 531).
- **Une table traduite à la main** est refusée deux fois : par la cohérence du sel et par l'engagement.
- **La garde de la copie lue d'`ouvrir`** (l. 1365 à 1370) sauterait en silence une clé suffixée : la traduction la rétablit.

### 5.2 La règle, décidée sur la table engagée elle-même (C4)

Rien de ce qui suit n'a lieu avant les gardes figées sur la table d'origine T :
- `exiger_table_coherente(T)` ;
- l'empreinte de T égale à `ENGAGEMENT-B5F` ;
- dans `ouvrir` seulement : l'égalité à `OUVERTURE-B5F` et les dates (C6).

Ensuite :
1. **Graphie.** Chaque famille de T se lit par le motif fermé `(?P<base>T(?:0[1-9]|10))(?P<relance>-x1)?(?P<retirage>-r1)?`. Toute autre graphie : refus (« suffixe inconnu »).
2. **Une seule graphie par base** dans T ; sinon refus (« deux graphies pour une famille »).
3. **Copie lue c(base)** : celle que donne la formation par les fonctions figées.
   - `preparer` la prend au champ « copie » de `resume_formation_depuis_branche`, qui la tire de la branche de la formation par `_familles_formees`.
   - `ouvrir` la prend au même champ du résumé, contrôlé par `exiger_copie_lue`.
4. **Décision, sur T elle-même** (qu'elle soit rangée ou non par nom) :
   - toutes les familles de T sont des bases : **variante (a)** ;
   - sinon, chaque famille de T égale c(base) : **variante (b)** ;
   - sinon : refus, nœud.
5. **Traces.** E_a et E_b sont les empreintes de T, dans son propre ordre, la famille de chaque ligne remplacée par sa base pour E_a, et par c(base) pour E_b (noms, membres et sel inchangés). La variante retenue a sa trace égale à l'engagement. Les deux traces s'écrivent au fichier de traduction (§ 5.3).

**`variante` est jouée dans tous les cas (C14).** En (a), toute la lecture est l'entrée figée.

### 5.3 La traduction contrôlée

- **Seulement en (b)**, après le point 4 : T_nu = T, chaque famille réduite à sa base ; noms opaques, membres et sel inchangés.
- **Puis les gardes figées des l. 529 à 532**, sur T_nu : famille dans `T01` à `T10`, membre connu, nom `X-NN`, aucune paire en double.
- **Ni la cohérence ni l'égalité à l'engagement ne sont jouées sur T_nu** : elles l'ont été sur T, avant.
- **Le fichier scellé `traduction-table-b5f.json`**, à côté du résultat, porte :
  - la table de traduction ;
  - E_a et E_b ;
  - l'engagement ;
  - `ERRATUM_SHA256`.
- **Format du résultat inchangé** (`b5f-resultat-lecture-v1`). Seul `a_garde_d_ouverture.code` change de contenu (C7) : en (b), il porte `{"commit": <commit de CODE-LECTURE-B5F>, "arbre_gele": "égal hors de la liste fermée de l'erratum", "commit_de_code": <commit v3>, "erratum_sha256": <ERRATUM_SHA256>}`, au lieu de `{"commit": …, "arbre_gele": "égal"}`.

### 5.4 Ce que cela touche dans le code figé

- **Rien n'est modifié.** `lecture_v1.py` reste à son empreinte, vérifiée par `programme_sha256`, appelée.
- **Le module d'ouverture recompose trois fonctions**, ligne pour ligne : `preparer` (l. 1480 à 1495), `garde_d_ouverture` (l. 516 à 535) et `ouvrir` (l. 1351 à 1385). Il le fait à trois remplacements près :
  1. les gardes de table sont jouées sur T ;
  2. la règle et la traduction sont placées avant les gardes de ligne, qui sont jouées sur T_nu ;
  3. la garde du code au commit est remplacée par (d'), (c'1), (c'2) et (b'), comme pour la commande.
- **Bornes (C6).**
  - `variante` et `preparer` vérifient la cohérence, l'engagement, la règle et l'épinglage, sans exiger `OUVERTURE-B5F`.
  - `ouvrir` vérifie tout.
- **Tout le reste est appelé tel quel** (liste du § 5.4 de la v1). Les objets privés sont récrits à l'identique, avec un essai d'égalité.
- **Non retenu** : vérifier les compagnons de `couts.json` et `formation.json`. Cela casserait la parité avec l'entrée figée (contre-lecture).

- **La ligne est inscrite avant la relance**, dans le commit de la marche neuf (C5).

### 5.6 Essais, écrits avant le code

**Montage de la branche de formation (C13, point 2).** On réemploie, en le déclarant, le montage des essais figés de `preparer`. À défaut, le monde fabriqué porte :
- les marches `AAAAMMJJ-HHMMSS-b5f-formation-<n>`, avec `-x1` pour une instance relancée ;

**Cas sain (b).** Un monde fabriqué par la fabrique figée (`epreuve_verite_plantee_v1.fabriquer`), et son jumeau suffixé :
- même sel ; une instance relancée, une famille retirée ;
- noms opaques redérivés ; renommage cohérent dans tous les fichiers du monde ;
- registre fabriqué recalculé.

**Parité.** Pour chaque monde de `liste_mondes()`, le rendu du traducteur figé est le même pour l'entrée figée sur le monde nu et pour l'ouverture recomposée sur le jumeau. Les mondes à artefact de table refusent tous deux. L'égalité exigée est fixée d'avance (C13, point 4) :
- exacte pour les codes, niveaux, motifs, rangs et comptes ;
- à 10⁻¹² relatif près pour les nombres réels, l'ordre des noms opaques pouvant changer l'ordre d'une somme.

**Témoins.**
- Table nue : variante (a) ; l'entrée figée passe ; le module neuf refuse.
- **Table dans un autre ordre que celui des noms** (C4), égale à son propre engagement : variante (a) si elle est nue, (b) si elle est suffixée selon la règle.

**Artefacts :**
- suffixe inconnu (`T03-y1`, `T03-x2`, `T03-r1-x1`, `T11`) ;
- deux graphies pour une famille ;
- table retouchée après l'engagement : refus par l'engagement, avant toute traduction, aucun fichier écrit ;
- graphie hors règle (C13, point 1) :
  - `-x1` sans ligne de relance ;
  - table mélangée, où `T03` porte son nom formé `T03-x1` et où `T05` est écrit nu alors que sa copie lue est `T05-r1` : ni (a) ni (b) ;
  - une table toute nue, elle, reste en (a) ;
- `OUVERTURE-B5F` différente de la table ;
- famille d'apprentissage dans la table ;
- doublon après traduction ;
- ligne d'épinglage absente du registre du commit prouvé ;
- (d'), (c'1), (c'2) et (b') comme pour la commande.

**Mutations qui doivent rendre un essai rouge :**
- traduire avant l'engagement ;
- tirer c(base) de la table ;
- admettre deux graphies ;
- oublier `-r1` ;
- jouer la cohérence sur T_nu.

### 5.7 Limites

- **Troisième graphie.** Une table écrite sur une troisième graphie (par exemple `-x1` sans `-r1` alors qu'un retirage a eu lieu) refuse au jour de l'ouverture : nœud.
- **Question fermée à la session de formation** (« graphie : nue, ou nom formé ? »), si elle est joignable. Elle reste au conducteur. Elle ne change pas le code, accordé d'avance.
