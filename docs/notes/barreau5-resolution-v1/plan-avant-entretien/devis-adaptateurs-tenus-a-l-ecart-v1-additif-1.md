## 6. Relevé de méthode

**Chaîne de raisonnement.**
1. Le devis scellé borne le stockage à 0,08 USD de l'heure et demande 300 Go pour la relecture (devis, § 1 et § 3, ligne « Carte » ; `dc886195…`).
2. Le code figé compte le stockage `storage_cost × 300 / 730` et refuse au-dessus de 0,08 (`git show c76e7916…:src/controle_ia/barreau5_familles/relecture_v1.py`, lignes 964-965 et 976 à 1004 ; empreinte du fichier au commit `f6bd8c15…`).
3. Au relevé, cinq offres passent les autres bornes si le prix lu est celui du relevé (disque de 8 Go compté), une seule si le prix est recompté à 300 Go ; dans les deux lectures, une seule a un stockage sous 0,12 (0,0986), aucune sous 0,08 (sortie du programme, parties 1 et 2).
4. Le prix du loueur au relevé est exactement `dph_base + storage_cost × 8 / 720` sur les 30 offres (sortie, partie 1) ; **supposé** : une recherche avec 300 Go de disque rend `dph_base + storage_cost × 300 / 720`, soit 1,26 pour l'offre admise.
5. Le coût de la relecture au plafond neuf : formules du calcul du devis (`calcul-devis-formation-trois-membres-v1.py`, `facb727a…`), rejouées ; contrôle sur les chiffres scellés (sortie, partie 3).

7. La borne n'est lue que côté session (`git grep` au commit : pas 2 ; lignes 547-548, 1053, 1071 à 1073).
8. Trois gardes interdisent un changement en place (`validation_reelle.py`, ligne 71 ; `engagement_v1.py`, lignes 131 à 145 ; R12) ; d'où le montage du § 3. **Supposé** : ce montage se code sans toucher un fichier existant ; je ne l'ai pas écrit ni éprouvé.
