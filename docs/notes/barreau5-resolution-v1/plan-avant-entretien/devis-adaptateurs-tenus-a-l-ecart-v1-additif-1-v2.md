## 3. Le code : la borne est dans le code figé, et la relecture la lit

**Où elle est.** Ce n'est pas un nombre de configuration : c'est une constante du module figé `src/controle_ia/barreau5_familles/relecture_v1.py` au commit `c76e79169eee337ce66c7d88f62d039e853eebfc` (ligne `CODE-LECTURE-B5F` : le code de lecture figé), lignes 964-965 : `OFFRE_LECTURE = {… "stockage_max_usd_h": 0.08 …}`. `git grep` au commit ne la trouve, dans le paquet, que là et dans `formation_v1.py` (ligne 1318, formation).

**Qui la lit.** `exiger_offre_lecture` (lignes 976 à 1004 : `storage_cost × disque de la pièce / 730`, refus au-dessus de la constante), appelée par `commande_de_creation` (ligne 1053), que joue la sous-commande « commande » de `scripts/lancer_b5f_lecture_v1.sh`, côté session. L'épreuve à vérité plantée (`EPREUVE-B5F`) est liée à l'empreinte de `lecture_v1.py` (`ed0999df…`), que rien ici ne touche.

**Pourquoi un seul nombre changé ne suffit pas.** Trois gardes du code figé s'y opposent, et aucune ne doit être contournée :
1. l'arbre gelé (`CHEMINS_GELES` : tout sauf `prereg`, `registres`, `docs` et les dossiers de sorties) du commit de la marche et de l'arbre de la session doit être celui du commit du code de lecture figé (`exiger_code_du_commit`, `lecture_v1.exiger_code_de_lecture_au_commit`), sur la session, sur l'instance (ligne 548) et à l'ouverture ;
2. le registre n'admet qu'une ligne `CODE-LECTURE-B5F`, jamais réécrite, et refuse toute clé inconnue ;
3. R12 : `relecture_v1.py` ne se modifie pas.

### 3.2 D'où se joue chaque sous-commande

**Seule « commande », version 2, se joue depuis le commit de commande.** Toutes les autres se jouent **depuis un arbre dont la partie gelée est celle du commit du code de lecture figé** (par exemple un arbre de travail extrait au commit de la marche), **jamais depuis le commit de commande**, avec le lanceur de la version 1 :
- **« verifier »**, juste avant la création : `verifier_avant_creation` appelle la même garde de l'arbre de la session (`relecture_v1.py`, ligne 876) ; jouée depuis le commit de commande, elle refuse ;
- **« ouvrir »** (l'ouverture) : `garde_d_ouverture` l'appelle aussi (`lecture_v1.py`, ligne 525) ;
- « scores », « preparer », « monde », « config », « detruire », « verifier-destruction » : même arbre, par la même règle, pour qu'une seule sous-commande sorte du code figé ;
- **« commande » pour la répétition générale** : version 1, même arbre (§ 3.3).

La session de lecture tient donc deux arbres de travail : l'un au commit de la marche, où tout se joue ; l'autre au commit de commande, où ne se joue que l'impression de la commande de création de l'instance de relecture. L'ordre reste celui de la version 1 : « config », « verifier » (arbre figé), puis « commande » (arbre de commande), puis création.

### 3.3 La répétition générale reste à la version 1

Le contre-lecteur laisse le choix : ou la vérification (d) ne vaut que pour la relecture décisive et le module neuf sert les deux pièces, ou la répétition reste à la version 1. **Je retiens : la répétition reste à la version 1 ; la sous-commande « commande » de la version 2 refuse le plan « repetition ».** Trois raisons :
1. **La borne de la répétition ne bouge pas** (0,08 USD de l'heure à 150 Go) : la version 2 n'aurait rien à lui apporter.
2. **Sans ligne d'accord de lecture, rien n'épingle le commit de commande pour la répétition.** Elle se joue sous l'accord de calcul de la formation (texte, point 18), dont la ligne est déjà inscrite et ne se réécrit pas. La vérification (b) n'aurait alors plus que (c) pour s'appuyer : « des fichiers ajoutés, de la bonne liste », sans que leur contenu soit cité nulle part. Ce serait une garde plus faible que celle de la version 1, qui exige l'arbre figé à l'octet. Servir la répétition par la version 2 affaiblirait une pièce que l'additif ne vise pas.
3. **Moins de surface** : une pièce servie, un chemin d'entrée, une seule ligne du registre concernée.

Ce choix coûte une chose : la répétition, si elle part, se commande depuis l'arbre figé (§ 3.2), ce qui est déjà son chemin d'aujourd'hui.

**L'égalité à l'octet est pourtant éprouvée pour les deux pièces.** Le corps recomposé garde les deux branches du plan, telles qu'en version 1 (c'est ce qui le rend comparable ligne à ligne) ; c'est la fonction d'entrée qui refuse « repetition ».
