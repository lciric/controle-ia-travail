## Majeurs

1. **Échéance du GO jamais contrôlée.** `scripts/lancer_hetzner_suite_tests_v1.py` L55 : `ligne.get("échéance")` — la garde (`lire_go`) nomme la clé `"echeance"` sans accent ; je l'ai vérifié : `l.get("échéance")` renvoie `None` pour GO-2026-11-28-04 alors que `echeance` vaut 2026-11-29. Le contrôle échoue en silence (R5). Correction : `ech = ligne.get("echeance")` ; `if not ech or ech < date.today(): sys.exit(...)` (un GO de calcul sans échéance lisible est refusé). Ajouter un essai : ligne GO échue, le lanceur doit sortir.
2. **Le plafond interne ne protège pas l'installation et le clonage.** Amorce L66-70 : `sur_term` n'appelle `arreter_essais` que si un groupe existe, puis revient ; le tir est unique. Si le TERM tombe avant les essais (bash le traite après la fin de la commande en cours, jusqu'à 2400 s), le script continue et lance pytest sans minuterie (modèle bash reproduit : « TERM recu », puis la suite repart). Commandes sans `timeout` : L257 `-m venv`, L259 `uv venv`, L263, L273-279 `git init/checkout`. Corrections : (a) `sur_term` : `if [ -n "$PGID_ESSAIS" ]; then arreter_essais; else exit 124; fi` ; (b) avant L296 : `[ "$DELAI_DEPASSE" = 0 ] || exit 124` ; (c) `timeout 300` devant `venv`, `uv venv` (L257, L259, L263).
3. **Aucune garde de durée sur la conclusion.** Amorce L203 tue le gardien, puis L188-189 `git push` et `git ls-remote` n'ont ni `timeout` ni limite de débit : une connexion figée empêche `detruire` d'être atteint. Corrections : `export GIT_HTTP_LOW_SPEED_LIMIT=1000 GIT_HTTP_LOW_SPEED_TIME=120` (L53) ; `timeout 600 git push …` ; `timeout 60 git ls-remote …` ; idem `timeout 120 python3 conclure.py` (L213).
4. **Identifiant du serveur obtenu en un seul essai.** L55-56 : un échec du `curl` de 10 s donne `inconnu`, et `detruire` (L223) renonce. Corrections : boucle de 5 essais espacés de 5 s ; dans `detruire`, si l'identifiant reste `inconnu`, le retrouver par `GET $HCLOUD_API/servers?name=$RUN_ID` (le lanceur nomme le serveur `run_id[:63]`) et n'agir que si exactement un serveur, d'identifiant numérique, est renvoyé.
5. **Aucun filet indépendant de l'amorce.** Les lignes 15-236 précèdent le piège EXIT (`:?` ou `exec` en échec, `set -u`), et un SIGKILL ou une panne mémoire de l'amorce, ou un échec de `systemd-run` (user-data L95), laissent le serveur vivant jusqu'au rempart externe. Correction recommandée (un seul ajout, qui couvre aussi 2, 3 et 4) : dans `donnees_demarrage`, avant le `systemd-run` de l'amorce, écrire `/opt/suite-tests/filet.sh` (0700 : identifiant par métadonnées avec 5 essais, vérifié numérique, en-tête dans un fichier 0600, 6 `DELETE` espacés de 30 s, sortie sur 200 ou 404) et le lancer par `systemd-run --unit=suite-tests-filet --on-active=$((plafond+2700))s /bin/bash /opt/suite-tests/filet.sh`. Éprouver sur le faux serveur d'API (essai : amorce volontairement tuée par SIGKILL, le filet supprime).
6. **`--lf` peut rejouer toute la suite en série.** Amorce L302 : si la première phase sort en code non nul sans échec enregistré (arrêt anticipé, erreur de collecte, worker mort), `--lf` sans `--lfnf=none` relance les 17 515 tests (vérifié : « 2 passed » avec cache vide ; avec `--lfnf=none` : « 2 deselected »). Correction : ajouter `--lfnf=none` ; garder la condition `!= 0 et != 5`.
7. **Lanceur : serveur orphelin possible.** L142 : `appel("POST", …)` n'attrape ni `URLError` ni expiration (60 s) ; le serveur peut exister sans que `--etat` soit écrit, et le repli peut en créer un second. L149 : l'écriture de l'état précède l'affichage. Corrections : `try/except (urllib.error.URLError, TimeoutError)` autour du POST ; sur toute exception ou tout code ≠ 201, relire `GET /servers` (ou `?label_selector=run=<id>`), et si un serveur existe, écrire l'état, l'afficher, sortir sans nouvel essai ; afficher l'identifiant avant d'écrire le fichier.
8. **Fermeture des métadonnées et des jetons non éprouvée.** `iptables -m owner` (amorce L251) et la lecture refusée de `/var/lib/cloud` ne sont jouées par aucun essai (R5 force `INSTALLER=non`, donc saute tout le bloc système) ; `|| exit 12` ne détecte que l'échec de la commande, non l'inefficacité de la règle. Correction : après L251, garde fermée à l'exécution : `if setpriv --reuid="$UTILISATEUR" --regid="$UTILISATEUR" --init-groups -- curl -s --max-time 5 -o /dev/null http://169.254.169.254/hetzner/v1/metadata; then echo "ARRÊT : métadonnées lisibles"; exit 13; fi` ; de même `setpriv … test -r /opt/suite-tests/jeton-github -o -r /opt/suite-tests/jeton-hcloud -o -r /var/lib/cloud/instance/user-data.txt` doit échouer, sinon `exit 13` (le piège EXIT détruit). Les essais R5 jouent déjà D pour le cas des fichiers de jetons.

## Mineurs

9. Amorce L286 : `git rev-parse HEAD` en super-utilisateur après `chown` (L281) échoue (« dubious ownership », visible dans le journal d'A) ; `commit=` reste vide dans `environnement-v1.txt`. Déplacer le bloc L285-290 avant L281, ou `git -c safe.directory="$DEPOT" rev-parse HEAD`.
10. L296 : `-q` sous xdist n'imprime que des points ; si le plafond tue pytest, le fichier junit n'existe pas (cas C : `phase_parallele: null`) et le journal est inexploitable. Remplacer `-q` par `-v` (une ligne par test, environ 2 Mo) pour que le rapatriement partiel serve.
11. L247 : aucun délai de verrou apt ; un `unattended-upgrades` au premier démarrage donne `exit 10`, donc un serveur détruit sans résultat. Ajouter `-o DPkg::Lock::Timeout=600` aux deux `apt-get`.
12. Lanceur, garde-fous manquants : refuser un `--depot-url` hors `lciric/controle-ia-travail` (CLAUDE.md : jamais `lciric/controle-ia`) ; valider `run_id`, branches par `^[A-Za-z0-9._/-]+$` (le fichier de paramètres est sourcé par bash) et nom de serveur valide ; vérifier par `git ls-remote` que `--branche-sortie` n'existe pas (sinon la poussée est rejetée, et la surveillance externe supprimerait le serveur 15 min après avoir vu une branche ancienne) ; refuser `--plafond-secondes` > 28800 ; refuser si prix horaire brut × plafond × 1,25 dépasse le plafond du GO (3 USD).
13. L206-218 : le serveur est détruit même si la poussée échoue (règle « récupérer ce qui est récupérable »). À 0,2 USD l'arbitrage est acceptable, mais ajouter avant l'abandon un second essai vers `${BRANCHE_SORTIE}-reduit` limité à `resume-v1.json` et aux xml compressés, et refuser tout fichier > 95 Mo avant `git add` (limite de GitHub, poussée tout entière rejetée sinon).
