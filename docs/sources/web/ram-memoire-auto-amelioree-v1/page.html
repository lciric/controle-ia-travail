Self-Improving Memory

Meta-Optimization and Harness Distillation for Continual Learning Agents

Overview

We want language models that get better at a task the longer they work on it. For an agent, this means managing memory well: what to write down, how to organize it, and when to read it back. Today these choices come from hand-written prompts, and no single prompt works best on every task. Self-Improving Memory lets the model discover these choices itself and then trains them into its weights. On three tasks from Continual Learning Bench, the prompts it discovers beat the best hand-written ones by 11.4 points (56.0 vs 44.6), and fine-tuning on runs with them gains 5.5 points over fine-tuning on the model’s own generic runs (43.1 vs 37.6).

Self-Improving Memory works in two stages. In harness optimization, a meta agent reads the task agent’s trajectories, finds where its memory use falls short, and rewrites the prompts that tell it how to use memory. Each new prompt is evaluated, and the best ones are kept for further revision. In harness distillation, the task agent runs with the optimized prompts, we swap those prompts back to generic ones while keeping the agent’s responses, and we fine-tune the model on the result. The meta agent and the task agent use the same model (Kimi-K2.6), so the model is trained on memory skills it discovered itself. Training carries part of the gain from better prompts into the model’s weights.

Motivation: Memory skills should be learned

Agents can improve with experience. An agent that works on multiple related tasks can pick up reusable knowledge from earlier tasks and apply it to later ones. Persistent memory makes this possible by letting information pass beyond the boundary of a single task. In our setting, every subtask starts in a fresh session with an empty context, and the only thing that carries over is a persistent memory directory that the agent reads and writes with file tools.

No single memory design wins on every task. Throughout this post, we use Continual Learning Bench as our evaluation framework, focusing on three of its tasks: Database, Codebase, and Spectrum. To motivate our approach, we conduct a small pilot study of several common, human-designed memory strategies. Each strategy is implemented through two prompts: one (OFFLOAD) that instructs the agent to offload what it has learned after completing a subtask (a process sometimes called dreaming), and another (LOAD) that instructs it to load relevant information before the next subtask. As Figure 2 shows, no single strategy performs best across all three tasks, consistent with the findings of Continual Learning Bench.

So the model should learn its own memory design. Rather than following a hand-written design, it should decide what to write, how to organize it, and what to recall. Self-Improving Memory does this in two stages, harness optimization and harness distillation, which we describe next.

Method: Self-Improving Memory

Our goal is to optimize a task model’s weights for continual learning tasks under a fixed generic harness. To achieve this, we propose Self-Improving Memory, which follows a Discover-Demonstrate-Distill pipeline: a meta agent first discovers memory-management skills through harness optimization, the task agent then generates trajectories that demonstrate these skills, and finally we distill the demonstrated skills into model weights. Because the meta agent and the task agent use the same model, this process updates the task model’s weights to internalize skills discovered by the model itself.

Setup: The generic harness

A task agent consists of a task model and a harness. We use a file system as persistent memory in our generic harness. The memory directory starts empty and persists throughout the task stream. The harness provides file-reading, writing, and editing tools, along with two task-independent instructions: LOAD and OFFLOAD. After each subtask is completed, an OFFLOAD prompt instructs the model to update its persistent memory based on the completed task interaction. The live context is then cleared. Before the next subtask begins, a LOAD prompt allows the model to load and retrieve relevant information from memory. The model may read memory files immediately at the start of a subtask (e.g., README.md) or defer doing so until later in the problem-solving process.

In the generic harness, the LOAD and OFFLOAD instructions are deliberately concise: they simply direct the model to manage its memory through file-tool calls while leaving the specific strategy to the model itself. However, performance may improve when these prompts prescribe a more specific, task-appropriate strategy. We explore how to discover such strategies in the next subsection.

Harness Optimization

Using persistent memory effectively requires deciding what information to retain, how to organize it, and when to retrieve it. Rather than requiring the task model to make all of these decisions independently, the LOAD and OFFLOAD prompts can provide explicit strategies. For example, they can specify when the agent should access memory or how it should organize information into tables, skill libraries, or entity inventories.

We propose a harness-optimization procedure that automatically discovers task-specific memory-management strategies. Our meta-optimization loop analyzes task-agent trajectories and compares alternative memory designs to identify LOAD and OFFLOAD instructions that maximize the task agent’s mean score (on a holdout set different from the train split that the meta agent can see).

The meta-optimization loop consists of a meta agent, which analyzes trajectories and task scores from the train subtasks to propose revised harness instructions, and an outer loop, which evaluates the resulting harnesses and uses the resulting task scores to select promising designs for further revision. We implement this search as follows:

  • Initialize the pool. We start with S human-written harnesses (i.e., pairs of LOAD and OFFLOAD prompts) representing summary, retrieval, skill-library, and hypothesis-tracking memory designs.
  • Evaluate the harnesses. For each unevaluated candidate, the task agent executes the full task stream N (e.g., 5) times, producing trajectories, subtask scores, and memory directories.
  • Select promising designs. We rank the pool by mean task score across the N runs and select the top P (e.g., 4) harnesses as parents for revision.
  • Analyze experience and propose new designs. For each parent, a meta agent analyzes the task agent’s message histories, subtask scores, and final memory directories from the training split. It identifies recurring failures and proposes revisions to the harness instructions. To handle the length and volume of the trajectories, the meta agent first summarizes each subtask, then analyzes each complete run, and finally consolidates evidence across runs into revised LOAD and OFFLOAD instructions. The revised harness from each parent is added to the pool as a new candidate for evaluation.

We repeat this procedure for a given number of iterations and select the highest-ranking surviving harness.

Harness Distillation

Demonstrate. We turn the discovered memory-management and task-solving behaviors into training demonstrations under the generic harness. For each task, we select the harness with the highest mean task score and run the base task model under this optimized harness on the train subtasks. We log every language model call, including its prompt, response, reasoning content, tool calls and arguments, and the corresponding tool responses. We then replace the optimized LOAD and OFFLOAD instructions wherever they appear in the recorded history with their generic counterparts. This replacement works because the demonstrated behavior stays compatible with the generic instructions: the optimized harness specifies a memory design, while the generic harness leaves those choices to the model. For example, compatible behaviors include organizing memory files (QUICKSTART.md for repository metadata, REGISTRY.md for reusable fixes, and SCHEMA.md for schema facts), recording useful facts (table relationships, column types, price units, timestamp encodings, and test commands), and reusing problem-solving strategies (running tests before editing, checking analogous functions, and verifying join keys before aggregation).

Distill. For $K$ tasks, let $\mathcal D_k$ denote the transformed demonstrations from the train subtasks of task $k$. We pool these demonstrations across tasks into a single dataset, reserving a validation split to monitor training. Each demonstration $\tau$ is represented as a token sequence $x^\tau$, with generic instructions and interaction history providing context.

We finetune model weights $\theta$ by minimizing the masked next-token prediction loss:

\[\mathcal L(\theta) = -\frac{1}{K}\sum_{k=1}^{K} \frac{1}{N_k}\sum_{\tau\in\mathcal D_k} \sum_{i\in A_\tau} \log p_\theta(x_i^\tau\mid x_{\lt i}^\tau).\]

Here $A_\tau$ indexes assistant tokens, including reasoning and tool calls, while instructions, task requests, and tool responses provide context and are masked from the loss. The count $N_k=\sum_{\tau\in\mathcal D_k}|A_\tau|$ is the number of supervised tokens for task $k$. Normalization by $N_k$ and averaging over $K$ tasks give each task equal weight. This objective trains the model to internalize the demonstrated capabilities in its weights and reproduce them under generic memory instructions.

Results

We use Kimi-K2.6 as both the task agent and the meta agent. Harness optimization begins with four human-written seed harnesses—Summary, Retrieval, Skill, and Hypothesis. We evaluate each harness over five repeated runs and select the top four harnesses for revision in each iteration. For harness distillation, we use LoRA with rank 64, applied to the attention projection layers. We use the first part of each Continual Learning Bench task stream as train subtasks and the later part as test subtasks. The split falls at a phase transition designed into Continual Learning Bench, so test results reflect generalization to new instances within the same task.

We compare four baseline settings during harness optimization. No Memory clears the base model’s context at each subtask boundary without retaining either a summary or a memory directory. Consequently, no information is carried across subtasks. Summary-Based Compaction summarizes the model’s context at each boundary and passes the resulting summary to the next subtask. Under the Generic harness, the model follows the task-independent LOAD and OFFLOAD instructions defined above, with files carrying information across subtask boundaries. Finally, the Human-Written harnesses are the seed harnesses evaluated in the first optimization iteration.

For harness distillation, we compare supervised fine-tuning (SFT) on two trajectory sets: SFT on Generic Trajectories, collected using the generic harness, and SFT on Optimized Trajectories, collected using the optimized harness. To train the Self-Improving Memory model, we rewrite the optimized-harness trajectories using the generic instructions. Both fine-tuned models and the No SFT reference model use the same harness during evaluation.

Automatic harness optimization delivers substantial gains

We select the best observed optimized harness separately for each task. Averaging the three selected task scores gives a mean of 56.0, an improvement of 11.4 points over the human-written seeds selected for each task and 19.9 points over Generic (Figure 4). The optimized harnesses improve over the selected human-written seeds on all three tasks, with the largest gain on Codebase (20.6 points). On Spectrum, Generic and Optimized have nearly the same raw first-subtask score (21.7 and 21.9), but reach test means of 42.5 and 49.9 as experience accumulates (Figure 6a). Both the human-written seeds and optimized harnesses are selected by task score, so these are the best observed scores among evaluated candidates.

Training internalizes part of these gains

We finetune on demonstrations from train subtasks and evaluate generalization to test subtasks of the same tasks after domain shifts. Across ten matched evaluation seeds, Harness Distillation reaches an overall mean test score of 43.1 versus 37.6 for SFT on generic trajectories, a gain of 5.5 points (14.6%, Figure 5). Its 7.0-point gain over No SFT (36.1, the same reference evaluation as Generic in Figure 4) is descriptive because the base model was evaluated separately. The improved test scores show that the finetuned model generalizes within the same tasks under domain shift, using generic memory instructions. We hypothesize that the gain partly reflects improved memory organization and retrieval, alongside task-solving behavior, but isolating this mechanism requires direct behavioral analysis.

Meta-optimization requires evaluation and selection

Across the completed searches (Figure 6b), 37 of 44 generated revisions fail to beat the best score from previous iterations. Database and Spectrum reach 53.8 and 49.9 in the first search generation and make no further gains, while Codebase improves through the fourth generation to 64.3. Progress therefore depends on evaluating proposals and retaining the best observed designs.

Its report identifies growing monolithic notes and repeated repository discovery. A revision that reuses recorded paths and retains failure rules scores 52.2. Conclusion

We present Self-Improving Memory, which improves a model’s memory-management performance by training it on better memory-management trajectories. We achieve this with a Discover-Demonstrate-Distill pipeline: the model discovers memory instructions tailored to each task, demonstrates them in its own trajectories, and is finetuned on those demonstrations so that it manages memory under a single generic harness. We observe that automatically optimized harnesses outperform human-written ones (56.0 versus 44.6 for the best human-written seed and 36.1 for Generic), and that distillation carries part of these gains into the model weights (43.1 versus 37.6 for training on generic-harness trajectories). We hope future work scales this approach to more agent capabilities beyond memory and to a wider range of tasks and models.

Related Work

Meta-harness optimization. An agent’s performance depends on its harness as well as its weights, yet harnesses are still largely designed by hand (Lee et al., 2026). Early work used language models to optimize prompts from feedback, by searching over candidate instructions or evolving populations of prompts (Zhou et al., 2022; Yang et al., 2023; Fernando et al., 2023; Agrawal et al., 2025). Later methods search over entire agent designs or let agents rewrite their own code (Hu et al., 2024; Zhang et al., 2024; Zhang et al., 2025). Recent systems optimize the harness itself, including coding-agent scaffolds, evolving playbooks, and skill harnesses (Lee et al., 2026; Lin et al., 2026; Zhang et al., 2025; Wei et al., 2026), and ALMA and MemEvolve apply this search to memory designs (Xiong et al., 2026; Zhang et al., 2025). The gains of an optimized harness, however, remain tied to that harness at deployment. Context distillation moves behavior induced by a prompt into the weights (Snell et al., 2022; Bhargava et al., 2024; Ye et al., 2026). WHALE and Co-Harness alternate harness search with fine-tuning (Kim et al., 2026; Chen et al., 2026), and Harness-Zero distills an optimized harness into a model that runs under a fixed one, using a separate agent to correct the student’s actions (Ye et al., 2026). Self-Improving Memory searches only the instructions that govern how the agent manages a memory directory across tasks. Because the optimized and generic harnesses differ only in these instructions, we distill by swapping the generic prompts back into the recorded trajectories, with no correction step. And because the meta agent and the task agent are the same model, the model learns memory skills that it discovered itself.

Memory and continual learning agents. Continual learning classically studies how a model improves over a sequence of tasks by updating its weights without forgetting earlier ones (Kirkpatrick et al., 2017; Parisi et al., 2019). Benchmarks for language agents recast this goal as using experience from earlier tasks to do better on later ones (Wu et al., 2024; Zheng et al., 2025; Wei et al., 2025). On Continual Learning Bench, which we use, agents often fail to reuse knowledge across instances, and dedicated memory systems do not fix this (Asawa et al., 2026). Memory systems either store records in an external database (Park et al., 2023; Packer et al., 2023; Xu et al., 2025; Chhikara et al., 2025) or write experience as text, such as reflections, skills, insights, workflows, and reasoning strategies (Shinn et al., 2023; Wang et al., 2023; Zhao et al., 2023; Wang et al., 2024; Suzgun et al., 2025; Ouyang et al., 2025). Deployed agents increasingly keep this memory as a directory of Markdown files that they edit with ordinary file tools (Zhou et al., 2026). In all of these systems, a human decides what to store and how to organize it. Yet no single memory-extraction prompt works best across task types (Yang et al., 2026), and memory that a language model keeps rewriting can become less useful than no memory at all (Zhang et al., 2026). Reinforcement learning can train memory managers, but mostly for question answering or within a single long task (Yan et al., 2025; Wang et al., 2025; Zhou et al., 2025), while Auto-Dreamer learns to consolidate memory offline across related tasks (Ye et al., 2026). Self-Improving Memory instead discovers the memory policy for each task, searching over LOAD and OFFLOAD instructions from four classic designs, and then distills that policy into the model’s weights so that generic prompts suffice at deployment.
