# 阶段 12b 预注册：三分类先验面板加入一个非 Claude 成员（2026-10-21，写于任何 12b 调用之前）

## 背景
阶段 12 的三分类先验面板只有 Claude 模型（Haiku / Sonnet / Opus）。审阅意见指出，"面板全是 Claude"会让"意外"只相对于一个模型家族。本阶段加入 GPT，检验阶段 12 的结论是否依赖面板构成。用户已批准（2026-10-21）。

## 设计
- **重测先验**：用与阶段 12 完全相同的三分类问卷（`s12.prompt`），请 GPT 给两个空间的全部格子打分。
  - 模型：gpt-6-astra，通过 codex-cli 0.162.0 调用（`s1.call('gpt', …)`）。
  - 调用数：NB201 29 批 + HPOBench 5 批，共 34 次；解析失败的批次重试一次。
  - 缓存：`out2/prior3_{nb,fc}_gpt_{i}.json`。
- **执行时间**：排在阶段 10（GPT 复现）之后，只在 Codex 额度允许时运行。
- **重新计分**：用已缓存的运行重新计分，不需要任何生成调用。

## 分析
1. **一致性**：比较 GPT 与每个 Claude 成员的三分类评分，报告 P(更高)、P(更低) 的相关系数，以及 P(无交互) 的均值。
2. **四成员留一面板**：生成模型为 Sonnet 或 Opus 时，面板为另外两个 Claude 模型加 GPT。在 4 个单元重算以下各项，判据与阶段 12 相同：
   - M3（A-100 − BASE 的 SV3，单侧置换检验，4 个检验做 Holm 校正）；
   - 测量臂和 judge 臂的 R，按多协变量校准，与 `s12_rmulti.py` 相同。
3. **只用 GPT 作面板**：所有单元都只用 GPT 一个评分者，重算 SV3 与 R。这是最"非 Claude"的版本。

## 判据（结论是否稳健）
- **稳健**：在第 2、3 项的两个变体下，都没有任何单元的测量臂出现显著增益（SV3 或 R，Holm p < .05），并且 judge 臂在两个 Opus 单元的 R 仍低于 BASE（p < .05）。
- **不稳健**：任一变体下，有单元的测量臂出现显著增益。这时论文中"测量不带来增益"的结论要限定为"相对于 Claude 面板"。
- **其余情况**：部分稳健，逐项报告。

## 事前预期
- GPT 也会把大部分概率放在"无交互"上。
- 结论稳健：测量在任何变体下都没有显著增益；judge 臂在 Opus 单元的 R 仍然更低。
- 我对"只用 GPT 作面板"这个变体最没有把握：单个评分者噪声更大，个别单元可能出现不显著的方向变化。

## 成本
约 34 次 Codex 调用，加最多约 5 次重试。不需要 Claude 调用。
