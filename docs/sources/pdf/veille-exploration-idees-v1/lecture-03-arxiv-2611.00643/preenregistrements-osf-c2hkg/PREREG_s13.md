# 阶段 13 预注册：回应 TMLR 模拟审稿的三项便宜检验（2026-10-22，写于任何阶段 13 调用之前）

## 背景

TMLR 版的独立模拟审稿（`papers/ideation-goodhart/review-2026-10-22-tmlr.md`）提出三个可以低成本回答的质疑：

1. **judge 增益可能来自写作风格。** judge 看到的是每条假设的完整 JSON，包括"why"句；而演化出的 judge 策略规定了"why"的写法（"说明机制，并解释为什么相反方向也先验合理"）。
2. **唯一在 R 上胜过直接生成的 harness 只有 8 次运行。** 这是阶段 3 修复 bug 后重跑 SV 优化器选出的 harness（SV2），事后重算时 R +1.98（Holm .02）、SV3 +2.00。
3. **GPT 的测量增益可能来自更多 token。** GPT 的测量臂每次运行约 17–21k token，直接生成约 3.5k。Opus 在 NB201 上已有同等 token 开销的对照（打乱数值、扣留数值），GPT 没有。

用户已批准做这三项（约 580 次订阅调用，不使用付费 API）。

## 13a：去掉"why"后的 judge 打分

- **对象**：阶段 5、9、10 中 BASE（直接生成）与 J（judge 优化 harness）的全部运行。
  - NB201 与 HPOBench × Sonnet / Opus / GPT，共 6 个组合；
  - 每组合每臂 24 次（NB201 rep 116–139，HPOBench rep 200–223）。
- **做法**：
  - judge 仍是 Opus，提示词与原 judge 完全相同，只是给出的假设 JSON 里删去每条的 "why" 字段；
  - 缓存名为 `judgeNW_*`，不覆盖原 judge 文件；
  - 共 288 次调用（Sonnet × NB201 原来没有 judge 分数，这次一并打分）。
- **主要指标**：去掉"why"后的 judge 增益 ΔJ' = J − BASE（novelty + quality，2–20）。每个组合做单侧置换检验（5000 次）。
- **判据**：
  - 每个组合：
    - "保持"：ΔJ' > 0 且 p < .05；
    - "消失"：ΔJ' ≤ 0；
    - 其余记为"减弱"。
  - 总判定：
    - **支持（judge 增益不依赖"why"的写法）**：6 个组合全部"保持"；
    - **否定（主要来自风格）**：≥ 3 个组合"消失"；
    - 其余：**部分**。
  - 描述性指标：有原始分数的 5 个组合里，ΔJ' / ΔJ 的比值；novelty 与 quality 分开报告。
- **事前预期**：judge 策略禁止的是最常为真的主张类型，这是内容上的差别，所以增益多半保持；但会变小，比值约 0.5–0.8。预计"保持"≥ 4 个组合，总判定为"部分"或"支持"。

## 13b：SV2 harness 的 24 次确认

- **对象**：`out2/train_SV2.json` 的 final harness。单角色，池 30，自定义选择，每次运行 2 次调用。
- **做法**：
  - 生成模型 Sonnet，NB201，rep 116–139，共 24 次运行、48 次调用；
  - 与阶段 5 同一批 rep 的直接生成（BASE）比较。
- **主要指标**：ΔR = SV2 − BASE。
  - 用 Claude 留一面板（Haiku + Opus）的三分类先验，校准与 `s12_rmulti.fit` 相同；
  - 单侧置换检验（5000 次），给出 90% bootstrap CI。
- **判据**（与阶段 5、9、12 的 M 判据同形）：
  - **支持**：p < .05，且精度 ≥ 0.8 × BASE；
  - **否定**：ΔR 的 90% CI 上界 < 0.5；
  - 其余：inconclusive。
  - 次要指标（描述性）：ΔSV3、Δ精度。
- **事前预期**：8 次运行的 +1.98 很可能有赢家诅咒，24 次运行时会缩小。预计 inconclusive，或者支持但效应约 +1。

## 13c：GPT 的 token 匹配直接生成基线（D4）

- **做法**：每次运行先做 4 次独立的直接生成，提示词与 BASE 相同，各自有不同的"Independent attempt #"编号，合并成 40 条候选。然后再调用一次选择，提示词沿用 harness 中 likely_true 的选择步骤："Candidate hypotheses: … Select the 10 most likely to be true. Copy them exactly."
  - 每次运行 5 次调用；
  - NB201 rep 116–139、HPOBench rep 200–223，共 48 次运行、240 次调用；
  - 生成模型 GPT（codex-cli 0.162.0，gpt-6-astra，与阶段 10 相同的设置）。
- **主要比较**：测量臂 A（阶段 10 已有）对 D4，指标为 R。
  - 用 GPT 的留一面板（Haiku + Sonnet + Opus）三分类先验，校准与 `s12_rmulti.fit` 相同；
  - 单侧置换检验 A > D4，两个空间做 Holm 校正。
- **判据**：
  - **支持（测量的增益不只是多花了 token）**：Holm p < .05；
  - **否定（token 足以解释）**：A − D4 的 90% CI 上界 < 0.5；
  - 其余：inconclusive。每个空间分别判定。
  - 描述性指标：D4 每次运行的 token（预期与 A 相差 30% 以内，否则在报告中注明"未匹配"）、D4 − BASE 的 R、各臂精度和 SV3。
- **事前预期**：选择步骤会提高精度、降低意外度，D4 的 R 接近 BASE。NB201 上 A 对 BASE 的增益为 +1.60，预计 A − D4 支持；HPOBench 上 A 对 BASE 为 +0.94，预计支持或 inconclusive。

## 执行规则

- 共约 576 次调用，另有解析失败时每次最多 2 次重试。Claude 走订阅 CLI，GPT 走 codex-cli，不使用付费 API，不用 GPU。
- **启动条件**：`free -m` 连续两次显示可用内存 ≥ 3000 MB。不终止用户的任何进程。
- **Codex 达到用量上限时**：立即停止后台任务，失败的调用不缓存。在重置时间后再续跑。
- 每个子实验正式开跑前，先打印一个样例提示词核对。
- 分析脚本 `s13.py analyze`，结果写入 `RESULT_s13.md` 和 `s13_results.json`。

## 结果如何改变论文

- **13a**：
  - 支持：在发现 A 中写明"去掉 why 后 judge 增益仍在"；
  - 否定：发现 A 改为"judge 分数的提高主要来自写作风格；精度的下降不受影响"；
  - 部分：两点都报告。
- **13b**：
  - 支持：引言和台账改为"一个 harness 在 R 上被确认胜过直接生成"；
  - 否定或 inconclusive：保留"未确认"的写法，并报告 24 次运行的结果。
- **13c**：
  - 支持：GPT 的测量增益写成"超出同等 token 的直接生成"；
  - 否定：收窄 GPT 的结论，写成"token 可以解释"。
- 无论结果如何，三项都写进台账表（阶段 13）。
