Claude in Amazon Bedrock (bedrock-mantle)

Call Claude through the Messages API on Amazon Bedrock’s bedrock-mantle endpoint, with AWS-native authentication, billing, and security boundaries.

This guide walks you through setting up and making API calls to Claude in Amazon Bedrock. Claude in Amazon Bedrock runs on AWS-managed infrastructure with zero operator access: Anthropic personnel have no access to the inference infrastructure. You can build sensitive applications entirely inside the AWS security boundary, with the same Messages API shape you use with the Claude API.



This page covers Claude in Amazon Bedrock, which serves Claude through the Messages API at /anthropic/v1/messages on the bedrock-mantle endpoint. That endpoint runs on AWS-managed infrastructure. The InvokeModel and Converse APIs, on the bedrock-runtime endpoint, are documented at Claude on Amazon Bedrock (bedrock-runtime). For an Anthropic-operated alternative on AWS with AWS Marketplace billing, see Claude Platform on AWS.

Access

Amazon Bedrock sets access criteria for each Claude model individually. Claude Fable 5.1, Claude Fable 5, Claude Opus 4.8, Claude Sonnet 5, Claude Opus 4.7, and Claude Haiku 4.5 are open to all Amazon Bedrock customers. For any other model’s criteria, check Amazon Bedrock model access in the AWS console. For region availability, see Regions.

Prerequisites

Before you start, ensure you have:

  • An AWS account with Amazon Bedrock model access enabled for the Claude models you intend to use
  • The AWS CLI installed and configured (optional, for credential management)

Authentication

Claude in Amazon Bedrock supports three authentication paths. Choose the one that best fits your security requirements.

Bedrock service role (recommended)

Use a Bedrock service role with AWS-managed keys for the most secure, long-lived access:

  1. 1

    Admin: provision the service role

    An AWS administrator provisions a Bedrock service role and grants developers iam:PassRole permission on the service role ARN.

  2. 2

    Developer: pass the role

    When you call the API, Bedrock assumes the service role on your behalf. See the Amazon Bedrock documentation for how to associate the role with your requests.

IAM assumed roles

For identity-federated access with a 12-hour maximum session:

  1. 1

    Admin: configure the IAM role

    Create an IAM role scoped to your Claude models. The trust policy names your identity provider (SAML, OIDC, or AWS Identity Center). The permissions policy grants bedrock-mantle:CreateInference only on the allowed model ARNs.

  2. 2

    Developer: authenticate and assume

    Authenticate through your corporate identity provider, then assume the IAM role. AWS STS issues temporary credentials that the SDK or CLI uses to sign requests.

Bearer tokens

A bearer token lets you call the endpoint without signing requests with AWS credentials. AWS calls this token an Amazon Bedrock API key. AWS recommends signing with temporary AWS credentials whenever possible, so bearer tokens are the least preferred of the three authentication paths. Use a bearer token when your software can’t sign requests.

Bearer tokens come in two types:

AspectShort-termLong-term
LifetimeUp to 12 hours, or until the AWS session that generated it ends, whichever comes firstUntil its expiration date. If it has none, it never expires.
PermissionsThose of the IAM identity that generated itThose of the IAM user that it belongs to
NotesWorks only in the AWS region where you generate itRecommended by AWS only for exploration

For either type, the IAM identity whose permissions the token carries needs the bedrock-mantle:CallWithBearerToken and bedrock-mantle:CreateInference permissions.

To use a bearer token:

  1. 1

    Generate the token

    Generate either type in the Amazon Bedrock console. You can also generate a short-term token with one of AWS’s token generator libraries. For instructions, see API keys in the Amazon Bedrock User Guide.

  2. 2

    Send the token

    How you send the token depends on how you call the endpoint:

    • With the SDK: Set the AWS_BEARER_TOKEN_BEDROCK environment variable. For how the client finds credentials, see Making your first request.
    • With direct HTTP requests: Instead of signing each request, pass the token in the x-api-key header or as Authorization: Bearer <token>. Leave out the request-signing parts, such as the x-amz-security-token header and cURL’s --aws-sigv4 and -u options.

Block long-term bearer tokens

An administrator can stop IAM users from calling Amazon Bedrock with long-term tokens. A token works on both Amazon Bedrock endpoints, and each endpoint has its own IAM action and condition key:

EndpointAction to denyCondition key
bedrock-mantlebedrock-mantle:CallWithBearerTokenbedrock-mantle:bearerTokenType
bedrock-runtimebedrock:CallWithBearerTokenbedrock:bearerTokenType

Write a policy with one Deny statement for each endpoint. In each statement, set Resource to *, and use StringEquals to require that the condition key equals LONG_TERM.

Where you attach the policy determines which tokens it blocks:

  • One IAM user: It blocks that user’s tokens. The Amazon Bedrock console creates a new IAM user for each long-term token, so this misses tokens generated there later.
  • A member account in AWS Organizations: As a service control policy (SCP), it blocks the tokens of every IAM user in the account, including new users.

The policy blocks using long-term tokens, not generating them. For a sample of this policy and for policies that control generation, see Control permissions for generating and using Amazon Bedrock API keys in the Amazon Bedrock User Guide.

Install an SDK

The client SDK supports Claude in Amazon Bedrock through a Bedrock-specific package or module.

Python
pip install -U "anthropic[bedrock]"

Making your first request

The endpoint follows the pattern https://bedrock-mantle.{region}.api.aws/anthropic/v1/messages. It uses standard SSE streaming and the same request body shape as the Claude API.

Pass the region when you create the client, or set the AWS_REGION environment variable. If you do neither, the Python, TypeScript, C#, Go, PHP, and Ruby SDKs try AWS_DEFAULT_REGION. The Java SDK reads the environment only when you call BedrockMantleBackend.fromEnv(), which uses the default AWS Region provider chain. That chain also checks your AWS config file and EC2 instance metadata.

For credentials, the client uses what you pass when you create it. Otherwise, the AWS_BEARER_TOKEN_BEDROCK environment variable takes priority over the client’s AWS credential chain, which includes the AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, and AWS_SESSION_TOKEN environment variables.

Python
from anthropic import AnthropicBedrockMantle

client = AnthropicBedrockMantle(aws_region="us-east-1")

message = client.messages.create(
    model="anthropic.claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello, Claude"}],
)

print(next(block.text for block in message.content if block.type == "text"))


You can also create the standard client with Anthropic: set base_url to https://bedrock-mantle.{region}.api.aws/anthropic and pass your bearer token as api_key. This path supports bearer-token authentication only. SigV4 signing requires AnthropicBedrockMantle.

Feature support

For the full feature list with Amazon Bedrock availability, see Features overview.

Supported feature highlights

  • Messages APIPreview with links to the API reference available — press Tab until focus enters the card, Escape to return. (/anthropic/v1/messages)
  • Prompt caching
  • Thinking
  • Tool use, including the Bash tool, Browser use tool, Computer use tool, Memory tool, and Text editor tool
  • Citations
  • Structured outputs

Features not supported

  • Input sources (URL sources for images and documents, Files API)
  • Server-side tools (code execution, web search, web fetch, advisor)
  • Agent infrastructure (Agent Skills, MCP connector, programmatic tool calling)
  • API endpoints (Message Batches, Models, Admin, Compliance, Usage and Cost)
  • Claude Managed Agents
  • Server-side fallback (the fallbacks parameter; use the client-side fallback pattern instead)

Regions

Claude in Amazon Bedrock is available in the following AWS regions. Amazon Bedrock offers two endpoint types:

  • Global: dynamic routing across all available regions for maximum availability. No pricing premium.
  • Regional: the endpoint resolves to the single AWS region you specify, for data-residency requirements. Regional endpoints carry a 10 percent pricing premium over global endpoints. To route across multiple regions within a geography, use an inference profile (US, EU, JP, or AU). Regions marked In-region only in the table support direct single-region routing without an inference profile.

The global endpoint is available for Claude Fable 5.1, Claude Fable 5, Claude Opus 5.5, Claude Opus 5, Claude Opus 4.8, Claude Opus 4.7, Claude Sonnet 5.5, Claude Sonnet 5, Claude Haiku 5.5, and Claude Haiku 4.5.

Quotas

Default quota is 2 million input tokens per minute (TPM). You can request up to 5 million input TPM and 500,000 output TPM without additional Anthropic approval. AWS enforces requests-per-minute (RPM) limits on the Bedrock side; contact AWS Support for RPM adjustments.

Data retention

Amazon Bedrock governs data handling for Claude in Amazon Bedrock. For details, see Data protection in Amazon Bedrock.

Monitoring and logging

Claude in Amazon Bedrock emits logs to both CloudWatch and CloudTrail. Anthropic recommends retaining activity logs on at least a 30-day rolling basis to understand usage patterns and investigate potential issues.

Support

For support, contact AWS Support or your AWS account team. Include your AWS account ID and the request-id from any failed API responses.
