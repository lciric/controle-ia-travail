Claude Models on Google Cloud (Google managed)

Copy page


Set up Claude Models on Google Cloud (Google managed), which Google operates as part of Google Cloud’s Agent Platform. Then, call Claude with the Anthropic SDK or cURL.

Copy page

Claude Models on Google Cloud compares the two Google Cloud offerings. It also shows how to tell which one you use.

Before making API calls

To use Claude Models on Google Cloud (Google managed), you need:

A Google Cloud project that can use Agent Platform. For setup steps, see Google Cloud’s [lien: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude] Anthropic Claude models on Agent Platform page.

The gcloud CLI installed, for local development.

For the identity making the calls, an IAM role that includes the aiplatform.endpoints.predict permission, such as Agent Platform User (roles/aiplatform.user). For details, see Google Cloud’s [lien: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/use-partner-models] Agent Platform partner models page.

Google Cloud credentials for that identity. To authenticate the SDK with Google Cloud, you might need to run gcloud auth application-default login. A cURL request to Claude Models on Google Cloud (Google managed) can get its token from gcloud auth print-access-token. That command uses the gcloud CLI’s own login, not Application Default Credentials, so run gcloud auth login or gcloud init before you use it.

Install an SDK

The client SDK supports Claude Models on Google Cloud (Google managed) through AnthropicVertex. Install the package that provides it:

PythonTypeScriptC#GoJavaPHPRuby

Python

pip install -U "anthropic[vertex]"


The ant CLI doesn’t support Claude Models on Google Cloud (Google managed).

Making requests

Requests to Claude Models on Google Cloud (Google managed) go to an Agent Platform endpoint URL that ends in :rawPredict. Streaming requests use :streamRawPredict instead.

A request is nearly identical to a Messages APIPreview with links to the API reference available — press Tab until focus enters the card, Escape to return. request. It differs in two main ways:

Model: The endpoint URL names the model. In a cURL request, leave model out of the body.

Version: In a cURL request, pass anthropic_version in the body and not as a header. Set it to vertex-2023-10-16 or to API version 2026-10-21.

The SDK handles both differences for you. It moves your model value into the URL and sets anthropic_version to the API version that it uses with the Claude API. For the model IDs to pass, see API model IDs.

In the following examples, the SDK client authenticates with Application Default Credentials. To set up Application Default Credentials, see Before making API calls.

The following examples use the global endpoint. For the other endpoint types, see Global, multi-region, and regional endpoints.

cURLCLIPythonTypeScriptC#GoJavaPHPRubyPython


from anthropic import AnthropicVertex

project_id = "MY_PROJECT_ID"
region = "global"

client = AnthropicVertex(project_id=project_id, region=region)

message = client.messages.create(
 model="claude-opus-5-5",
 max_tokens=100,
 messages=[
 {
 "role": "user",
 "content": "Hey Claude!",
 }
 ],
)
print(message)

Global, multi-region, and regional endpoints

Claude Models on Google Cloud (Google managed) offers three endpoint types. You choose one with the region value you pass when you create the client. In a cURL request, the endpoint type sets the host and the locations segment of the URL.

Endpoint type
Region value
Host

Global (recommended)
"global"
aiplatform.googleapis.com

Multi-region
"us" or "eu"
aiplatform.us.rep.googleapis.com
aiplatform.eu.rep.googleapis.com

Regional
A region, such as "us-east5"
{region}-aiplatform.googleapis.com

The endpoint types differ in where they send requests:

Global: Requests go to any region with available capacity. Use it when you want maximum availability and data residency is flexible.

Multi-region: Requests go to any region in the United States ("us") or the European Union ("eu"). Use it when you need data residency within a broad geography and higher availability than a single region.

Regional: Requests go only to the region you name, such as "us-east5" or "europe-west1". Use it when you need single-region data residency or must meet strict compliance mandates.

Multi-region and regional endpoints cost 10 percent more than global endpoints. All three endpoint types take pay-as-you-go traffic, and provisioned throughput needs a regional endpoint.

Regional endpoints serve Claude Sonnet 4.6 and earlier models only. For newer models, use a global or multi-region endpoint.


The premium for multi-region and regional endpoints applies only to Claude Sonnet 4.5 (deprecated) and later models. For the models that keep their earlier pricing, see [lien: /docs/en/about-claude/pricing#cloud-platform-pricing] Cloud platform pricing. For regional endpoints, the premium reflects infrastructure costs for dedicated regional capacity.

The following examples use the us multi-region endpoint. The highlighted lines set the region. For a full request on the global endpoint, see Making requests.

cURLCLIPythonTypeScriptC#GoJavaPHPRubyPython


from anthropic import AnthropicVertex

project_id = "MY_PROJECT_ID"
region = "us" # Multi-region identifier: "us" or "eu"

client = AnthropicVertex(project_id=project_id, region=region)

Features not supported

Claude Models on Google Cloud (Google managed) doesn’t support the following:

Input sources: URL sources for images and documents, and the Files API

Server-side tools: Code execution, web fetch, and advisor

Agent infrastructure: Agent Skills, MCP connector, and programmatic tool calling

API endpoints: Message Batches API, Models API, Admin API, Compliance API, and Usage and Cost API

Claude Managed Agents

Server-side fallback: The fallbacks parameter

Instead of server-side fallback, use the client-side fallback pattern.

Billing, rate limits, and logging

Rate limits

Google Cloud manages rate limits and quotas for Claude Models on Google Cloud (Google managed). For details, including how to request a quota increase, see Google Cloud’s [lien: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas] Quotas for Anthropic Claude models page.

Billing

Google Cloud invoices you for Claude Models on Google Cloud (Google managed). For prices, see Google Cloud’s Generative AI pricing page. Prices also depend on the endpoint type. See Global, multi-region, and regional endpoints.

Data retention

Google Cloud governs data handling for Claude Models on Google Cloud (Google managed). For details, see Agent Platform and zero data retention.

Monitoring and logging

To log prompts and completions for Claude Models on Google Cloud (Google managed), use Agent Platform’s request-response logging service.

Anthropic recommends that you keep at least the last 30 days of logs. The logs help you understand your activity and investigate possible misuse.


Turning on this service doesn’t give Google or Anthropic any access to your content.

Migrating from Claude Models on Google Cloud (Anthropic managed)

For what changes when you move, see How the two Google Cloud offerings differ. To move to Claude Models on Google Cloud (Google managed), follow these steps:

1

Set up access
Check that your project and the identity that makes the calls meet the requirements in Before making API calls.

2

Install the SDK package
Install the package that provides the client for Claude Models on Google Cloud (Google managed). See Install an SDK.

3

Replace the import and the client
Change the code that imports and creates your client. Use AnthropicVertex in place of AnthropicGoogleCloud. A cURL request needs a new URL, new headers, and a new body. The following code creates the client for Claude Models on Google Cloud (Anthropic managed) that you use today:

cURLCLIPythonTypeScriptC#GoJavaPHPRubyPython


from anthropic import AnthropicGoogleCloud

client = AnthropicGoogleCloud()
The following code creates the client for Claude Models on Google Cloud (Google managed). It uses the global endpoint. For the other endpoint types, see Global, multi-region, and regional endpoints.

cURLCLIPythonTypeScriptC#GoJavaPHPRubyPython


from anthropic import AnthropicVertex

project_id = "MY_PROJECT_ID"
region = "global"

client = AnthropicVertex(project_id=project_id, region=region)
This code passes your project ID and a region when it creates the client. Replace MY_PROJECT_ID with your project ID. The Messages API calls that you make with the client stay as they are. The exceptions are the model IDs and features in the next step.

4

Check model IDs and features

Model IDs: If you use a model earlier than Claude 4.6, replace the hyphen before the snapshot date in its ID with @. For example, claude-haiku-4-5-20251001 becomes claude-haiku-4-5@20251001. For the models and their IDs, see API model IDs.

Features: Check that the features your code uses aren’t listed in Features not supported.

5

Run a test request
Run the request in Making requests to check that your setup works. Then run your own code. Before you move production traffic, read about rate limits for Claude Models on Google Cloud (Google managed).
