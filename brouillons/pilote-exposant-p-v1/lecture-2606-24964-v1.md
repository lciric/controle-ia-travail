## 5. Écarts entre le texte et le code (relevés, non tranchés)

1. Colonne « Model » de l'audit : filtre de recouvrement de Gemma appliqué en plus de celui du modèle (318 paires pour Llama au lieu de 340).
2. Seuil d'exclusion : le texte dit « < 0,1 », le code garde « ≤ 0,1 ». Sans effet pratique.
3. Le `README.md` présente le seuil fixe par condition (`refit_thrfixed_all.py`) comme « the canonical paper protocol ». Les figures et l'audit utilisent pourtant le seuil par paire (`_thrpair_exact`), comme le texte (éq. 3, note 1). Le `README` est en partie périmé.
4. Trois directions du code (`Formal`, casual → formal ; `HonestyShort` ; `TensePresent`) sont mesurées puis retirées au tracé comme « redondantes ». `Formal` est une direction de **registre** : sur Llama, ses 32 paires ont des p de 1,74 à 3,46 (calcul), et `cos(Formal, Literary) = 0,287`.
5. Le script `random_diff_directions.py` vaut par défaut `k_avg = 1` (différence unique) ; la famille du papier est `k_avg = 30`, conforme aux éq. 6 et 7.
6. La référence non perturbée est passée seule (lot de 1). Les points perturbés passent en lots de 64. Les arrondis de `bfloat16` donnent un plancher de L2 de quelques unités à l'origine (docstring de `sweep_core.py`) ; sur les grilles de Llama, ce plancher vaut 0,66 en médiane, 1,67 au plus (calcul), contre un seuil T de 10 à 18.
7. Les grilles publiées montent de façon régulière de 0 à 60°, presque linéairement aux petits angles, sans plateau franc. Le maximum de chaque axe est au bord (60°). L'hétérogénéité entre ancres est forte : 4 ou 5 ancres sur 30 ne franchissent pas T dans la fenêtre sur un axe ; l'écart type du logarithme de l'amplitude vaut 0,5 (calcul).
