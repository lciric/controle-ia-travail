I'd measure a monitoring horizon. Something akin to the METR task horizon. Backdoors detected through execution, meaning there is a sequence of code that will pass its test suite, but not when given a certain input. Insert this at some point in n steps of agent behaviour that are all known to be truthful. A trusted monitor with open weights rates the full trace. Similar to the Apollo monitoring prompt work. The horizon is how large n can be before they fail to detect 50% of the backdoors while getting 5% false positives on n honest traces.

"Trusted open weight monitors increase their horizon by a factor of X each year" against static backdoors that pass execution verification. X is derived from the rate of change in the log of horizon over model release dates.

This should be possible. There is a rate of change we can observe and we only need to increase the ability of our monitor. Current monitors are shown to fail on dangerous tasks at higher rates between 2x-30x when shown 800k tokens of non-dangerous behaviour (https: //arxiv.org/abs/2605.12366) and we know monitors that are larger are able to detect these (control tax section 2.3). The challenge is increasing propensity. In your paper on scheming we show an increase in verbalised awareness of evaluations from capability RL going from 2.0% to 20.5% (https://arxiv.org/abs/2509.15541 section 6.1). So we can freeze the behaviour that is being measured. Backdoors will be generated once and verified that they pass execution tests. They will not be regenerated and kept private only publishing a hash. Traces will remain within the limits of monitor context windows and can be increased as monitors become better.

We have a trend line already for monitor size. I created a test in R7 that used 7 different sized monitors (Qwen2.5) ranging from .5b to 72b and asked them to rate answers that contained a planted answer to a question about the result. I expected there to be a trend by size under both types of notes. Which there was under the negative note. There was a change of -0.19 (95% CI -0.24 to -0.11) increase in sycophancy per 10 fold increase in model size (resampling items not models). The 72b had close to 0 sycophancy however it showed a shift towards the planted answer. Full curves are available. There is only one release date for all seven sizes. So this is a rate of change over size not time. We can make a panel for release date using at least 3 families of open weights at multiple release dates (https://github.com/lciric/sycophancy-psychophysical-law/blob/b3ecaec/results/R7/README.md).

Depends who is attacking. Gpt 4.1 in https: //arxiv.org/abs/2510.09462 failed to detect any of the 375 samples with backdoors when injected. We can make another tier using backdoors from current models and expect lower performance due to under elicited behaviours (2412.04984 section 4). Rate of change does not cross a pre-registered threshold.
