## 2. Définitions (mécaniques ; aucun jugement après V1)
- **États de V1** (G « Métrique ») : tenu (T) ; **A** « non tenu — absent » ; **G** « non tenu — négatif » ; **V** « non tenu — invalide » ; **C** « non concluant ». Les quatre ensembles A, G, V, C sont disjoints.
- **Classe lue d'un produit** (T5) : pour un produit de verdict ou de lecture dont la colonne « classe lue » est « oui » (§ 3), le lecteur copie la classe que la fiche du critère dans la grille (« États ») donne à la valeur copiée en T3 : **négatif** = ce que la fiche nomme « non tenu — négatif » (G l.74 ; fiches : l.173-174 pour 1, l.218-219 pour 2, l.251-252 pour 3, l.297-298 pour 5) ; **établi** = ce que la fiche appelle la preuve du critère (toutes les lignes exigées le prononcent) ; **autre** = le reste. Le produit prend la pire classe de ses lignes (négatif > autre > établi) ; il n'y a pas de classe pour un produit absent. Le critère 4 n'a pas de « négatif » dans la grille (absent, invalide, non concluant) : P-B4 n'a pas de classe lue. Le lecteur copie la classe, il ne la juge pas ; si la valeur copiée n'appartient à aucune fiche, la classe est « autre » (jamais « établi »).
- **Gel effectif G'** (L2, L2bis) = G ∪ `gel` ∪ {k : classe lue de P_k = négatif} ; `gel` = G' de l'étape précédente (le gel ne se lève jamais). **A'** = (A moins les critères que le constat du 31 décembre déclare « présents ») moins G'. Avant le constat, A' = A moins G'.
- **Produit** : pièce de la colonne « produits ». **Tests d'un produit** à un commit `C` de `main` : T1 (M-0.6) chaque chemin du motif existe à `C` (§ 3) ; T2 (M-0.1) son compagnon `.sha256` est dans le même commit et `python -m controle_ia.scellement verifier` rend OK ; T3 (M-0.5, produit de type verdict) pour chaque ligne de la table gelée du préenregistrement qui nomme « critère k de G0 », le verdict contient le même texte avec sa valeur, copiée et non lue (D-G0-8) ; T4 (M-0.2, type préenregistrement) `exiger_prereg_scelle` rend l'empreinte ; T5 : classe lue. Un produit est **présent** s'il passe T1, T2 et, selon son type, T3 (verdict) ou T4 (préenregistrement) ; **absent** sinon. Un verdict négatif scellé est présent. Le script exécute T1, T2, T4 (`tester`) ; T3 et T5 sont copiés par le lecteur (`val=`).
- **Étape et date d'usage.** Une étape est un lancement (run, location, appel payant) ou un scellement d'une ligne K, ou d'une ligne I ou R dont « sert » est non vide ou qui engage une dépense facturée (les passations, R14, et les poussées n'en sont pas). La session qui la fait écrit **seule, dans un commit à elle**, une ligne dans `registres/etapes.md` (à créer, routine) : réf. de la ligne, nature, `gel` copié de la feuille précédente. Le commit de départ de l'étape est **le parent** de ce commit : les tests T1 à T5 et `feuille` sont évalués à ce parent ; un produit scellé après ce parent ne compte pas pour cette étape. Une lecture de deux familles compte deux étapes. Un produit dont le run s'est achevé avant l'étape mais qui n'est scellé qu'après est signalé en réserve par le lecteur du second verdict (datation du manifeste).
- **†** : dépendance déduite (B l.146-152 : le harnais de T0.4 produit les épisodes et les activations de tout run ; B l.141 et l.214-217 : les bras séquentiels de G1 emploient les agrégateurs de T0.3 ; PG l.38 : le pilote précède le « passage sur les vrais écarts », non le scellement), non écrite par une source. **‡** : le produit doit avoir la classe lue « établi », non seulement être présent (source : SY § 2 pt 9 et R-765, dont le défaut majoritaire débloque 3 et 4 « par un statut “2 tenu” prononcé, jamais par empreinte ni dossier scellé »).
