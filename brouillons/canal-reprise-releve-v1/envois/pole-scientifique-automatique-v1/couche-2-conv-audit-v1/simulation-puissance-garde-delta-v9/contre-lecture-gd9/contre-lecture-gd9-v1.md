## (b) Vérifications ciblées sur les sorties JSON

**Table en ρ̂ à 288 unités.** Les valeurs demandées sont reproduites exactement : ρ̂ = 0 → 288 / 304 (ρ_haut 0,0145) ; 0,05 → 288 / 352 (0,0702) ; 0,10 → 320 / 416 (0,1248) ; 0,17 → 416 / 544 (ρ_haut 0,19992) ; muette au-delà. Pour les deux hypothèses, la ligne retenue est 0,05 / 0,025 ; 0,10 / 0,085 ; 0,125 / 0,125 ; 0,20 / 0,20 respectivement. Je retrouve aussi T1 en entier (n80 pire, n90 pire, n_h avec enveloppe croissante) pour les 17 lignes, depuis les sorties brutes : 0 différence. La table est monotone dans ρ̂ (0 violation sur 401 points).

Règle définie partout : oui, sur le domaine annoncé (ρ̂ de 0 à 0,40, trois tailles de pilote 50, 100, 288) la fonction rend une taille ou « hors table », jamais d'erreur ; ρ̂ négatif est ramené à 0 (`max(ρ̂ ; 0)`). Premier ρ̂ hors table, lu sur des réels : 0,1701 (288), 0,1467 (100), 0,1273 (50) ; avec l'hypothèse ρ_A = ρ_B seule : 0,31 ; 0,2858 ; 0,2563. Trois réserves, toutes de présentation :

1. **Pas de 0,01.** Les intervalles de T2 sont calculés aux centièmes exacts. Sur des réels, les marches sont ailleurs : à 288 unités, 288 / 320 dès 0,005 ; 352 dès 0,030 ; 368 dès 0,061 ; 320 / 416 dès 0,076 ; 384 / 496 dès 0,101 ; 416 / 544 dès 0,141. Un ρ̂ de 0,104 arrondi **au plus proche** (0,10) lirait 320 / 416 au lieu de 384 / 496 : non prudent. Arrondi **au centième supérieur**, la table est toujours au moins aussi prudente que la règle exacte et le bord « hors table dès 0,18 » devient exact (ρ̂ > 0,17). Le rapport ne dit pas quel arrondi (résumé 2, T2, option A « ρ̂ ≥ 0,18 »).
2. **Bord à ρ̂ = 0,17 dans le bruit de simulation.** ρ_haut = 0,17 + 1,645 × 0,018187 = 0,19992 ; la ligne 0,20 est atteinte parce que l'écart-type pourrait grandir de 5 × 10⁻⁵ (0,3 %) avant de basculer en « hors table ». L'erreur de Monte-Carlo de cet écart-type (2 000 répétitions) est de l'ordre de 1,6 %, soit dix fois plus. Le chiffre « 0,17 → 416 / 544, muette dès 0,18 » est donc exact comme **table gelée**, mais pas comme grandeur robuste : à écrire tel quel, avec les écarts-types en entrée, pas comme propriété du monde.
3. **Taille de pilote.** La règle est définie pour 50, 100, 288 seulement ; la phrase du § 11 la restreint à 288 : correct.

**Neuvième comparateur en n_h.** Refait depuis les sorties v8 brutes (`neuf-k8` / `rho0`, `meme-…`, `neuf-k9-g0.05-…`, `neuf-k9-g0.10-…`, quatre cellules, pire, 1,06, multiple de 16, plancher 288) : seuil 40, n_h à neuf comparateurs 288 / 400 / 496 / 512 / 544 / 736 (nulle, ρ 0,05, bêta, logit, ρ 0,10, ρ 0,17) soit **288 à 736** ; écarts **+0 / +112 / +208 / +224 / +256 / +432**, soit **+0 à +432**. Seuil 160 : 368 / 544 / 672 / 672 / 736 / 976, soit **368 à 976** ; écarts +80 / +240 / +368 / +368 / +400 / +592, soit **+80 à +592**. À écart 0,10 : inchangé au seuil 40 partout, +16 au seuil 160 en bêta σ = 1,0 seulement. Tout concorde avec le rapport et avec la correction de GD8 (+0 à +432 ; +80 à +592 ; 288 → 288 sans dispersion).

**Puissances moyennes.** Refaites depuis les neuf sorties (graines 20261029 et 11 à 18), pire des quatre cellules par graine, puis moyenne et erreur type (écart-type / √9) : 288 unités seuil 40 : 0,8395 ± 0,0026 (rapport 0,840 ± 0,003) ; seuil 160 : 0,5062 ± 0,0031 (0,506 ± 0,003) ; 400 unités seuil 40 : 0,9799 ± 0,0012 (0,980 ± 0,001) ; seuil 160 : 0,9083 ± 0,0019 (0,908 ± 0,002). Rien à corriger, sauf à ne pas écrire « 16 / 16 au critère scellé » sans rappeler la faute de décompte (le rapport la rappelle : lignes 365 et 418).

## (e) La phrase proposée pour le préenregistrement de G1 (§ 11)

Exacte pour tous les nombres : 0,840 ; 0,506 ; 0,980 ; 0,908 et erreurs types ; 288 / 288 / 320 / 416 et 304 / 352 / 416 / 544 ; 304 / 384 et 384 / 496 au ρ vrai ; +16 / +16 / +64 pour le ρ honnête double ; 288 à 736, 368 à 976, +0 à +432, +80 à +592. Quatre passages plus forts ou plus lâches que les sorties :

1. **« ρ_haut = ρ̂ + 1,645 × écart-type de lecture »** : le calcul utilise max(ρ̂ ; 0) + 1,645 σ, avec σ lu à la plus petite valeur de la grille de précision (0, 0,05, 0,10, 0,125, 0,17, 0,20, …) au moins égale à ρ̂. À la lettre, un ρ̂ négatif (probable un cas sur deux à ρ = 0) donnerait un ρ_haut plus bas et une ligne plus petite que celle du calcul (ex. ρ̂ = −0,02 : ligne 0 au lieu de 0,05, donc 288 / 288 au lieu de 288 / 304). À corriger : écrire `max(ρ̂ ; 0)`, la règle de σ, la table des σ (ou son empreinte), et « ρ̂ arrondi au centième supérieur ».
2. **« Un neuvième comparateur d'écart de contraste 0,10 ne change pas ces tailles (+16 au plus) »** : le contrôle porte sur les tailles au ρ vrai de l'hypothèse ρ_A = ρ_B jusqu'à ρ = 0,17 (T3), non sur les tailles lues en ρ̂ (lignes jusqu'à 544) ni sur l'hypothèse ρ_A = 2 ρ_B. À restreindre à « aux tailles au ρ vrai jusqu'à 0,17 sous ρ_A = ρ_B ».
3. **« biais ≤ δ/4 »** : seuls les biais 0 et δ/4 sont simulés ; écrire « biais dans {0 ; δ/4} ».
4. **ρ honnête double** : correct pour le seuil 160 ; au seuil 40 à ρ = 0,17 l'effet est +32 (304 → 336), non cité dans la phrase (omission, pas excès).

Aussi : « au-delà de ρ̂ = 0,17 (288 unités) la table ne répond pas » est la formulation exacte (réels) ; le résumé 2 et l'option A, « dès ρ̂ ≥ 0,18 », ne le sont que sur la grille au centième, d'où l'arrondi de (b.1). Références mortes : la phrase de la ligne 204 renvoie à « § 0, § 10 » (le § 0 n'existe pas dans ce rapport) ; le tableau du neuvième comparateur garde un « seuil 160 » à 8/α_c pour 9 comparateurs, hérité de la v8 et non modifié : à confirmer par l'auteur que cette référence reste voulue avec dix-huit processus (je ne l'ai pas tranché).
