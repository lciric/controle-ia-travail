Writing sample 2 — White-Box Control of Diffuse Threats

Extract of a research proposal, Lazar Ciric, October 2026 (sections 1–5 of 8), rewritten for this application (references specific to the funder it was written for removed).

Building up evidence internally over time and across agents and testing how susceptible the monitor is to corruption

1. Summary

Most current AI control monitoring looks at actions one at a time. This does not work against diffuse threats by definition. If an AI agent is doing research it can nudge many decisions in a bad direction (less stringent controls, dead ends, higher costs) and never do anything that would trip a monitor that looks at actions individually. Multiple instances of the same model can do the same thing by splitting a malicious modification into chunks that are individually harmless. I will use pre-registered decisive experiments to determine if there is evidence that builds up internally in the agent. Paper A will build up probe scores over time using an anytime valid guarantee on false alarms. Paper C will consider the monitor as an attack surface. It will measure how much persuasion can move LLM judges and activation probes. How much it costs an attacker to move a probe. And if a benign test can predict when a monitor will give in to an optimized attack. Paper C and A will be done in a 7 month period with C coming first. C builds on a law I have already observed and the result will not hinge on the outcome of A. Paper B which will build up evidence across agents that share weights will be an extension. The theory consists of a lemma about additivity and a negative theorem for permutation groups over time and agents. A pre-registered simulation has validated all 31 predictions. This validates the statistical methods, not the claims about real models. Phase 0 has also validated the method of logging activations on Llama-3.1-8B-Instruct within certain bounds of hardware and context length. There is a pre-committed course of action and criteria for each gate, sealed before any data. Negative results will be published.

2. Problem

If an agent can sabotage in a diffuse manner they will defeat monitoring that looks at actions individually. Developers are beginning to allow AI agents to perform some tasks in AI research. If that agent is misaligned they do not need to do something overt. The most efficient way to sabotage is to subtly bias many decisions. Terekhov et al. ("Diffuse AI Control on Fuzzy Tasks", arXiv 2606.08892) created a control setting around this. They look at ways to mitigate this with training because monitoring and incrimination "seem theoretically and empirically less promising for mitigating diffuse threats" (p. 2). If you are comparing actions to a threshold based on honest behavior you can only detect if that action is unusual. You need to build up evidence to detect if no individual action is unusual. This can also happen across multiple agents. Attacks that span multiple agents, sessions or merge requests can get past monitors that look at one at a time (arXiv 2607.07368, 2605.31593, 2607.02514). Having one monitor that watches everything is expensive. The monitor can be attacked. The agent can talk to its monitor. There is evidence that monitors that control AI: Can be influenced by the agent's rhetoric (arXiv 2505.23575); Will accept a score given to them by an attacker (arXiv 2510.09462); Can be persuaded by the agent and measured by approval rate (arXiv 2607.08066). It is cheap for an attacker to avoid activation probes if they can fine-tune the weights (arXiv 2609.36490). They found that from just the context the shift was not large enough to evade. We have not found any work that measures the cost of moving a probe as a function of attack type and strength. Or compares it to the cost of moving a judge.

Why white-box. If a developer is using agents internally they have access to their activations. If there is some internal signature that an agent intends to sabotage then we can build up evidence internally even if we cannot externally. We do not know if this is true for realistic model organisms. This project will find out and pre-commit to what happens next.

3. Theory: A Lemma, Negative Theorem and Key Question

Let Xi,t be the monitor score for agent i ∈ {1,...,N} and step t ∈ {1,...,T}. Time (N = 1) and Swarm (N = k) are equivalent objects. They each map to a subgroup of the permutations over the indices. Permuting time within an agent and permuting agents within a step. This allows us to have one theory that covers both Paper A and Paper B.

Lemma (L) about additivity in the adversarial case. The attacker distributes their budget B = Σδk of mean shifts across agents, steps, timing, value and position. They can do this adaptively. The defender maintains an anytime valid guarantee on false alarms.

  • Terminal invariance. The terminal sum will be shifted by B no matter how it is distributed. So its power only depends on B, the horizon n₀ = NT, the distribution of honest scores and alpha. Given B it will decrease as n₀ increases.
  • Contrast with the max. With an exact threshold, the per-action max loses its power as you fragment the attack.
  • Anytime valid interpretation. It is better for the defender if the sabotage happens early and worse if it happens late. There is a lower bound that only depends on (B, n₀) for any schedule. We can quantify how much it hurts to wait and how much it costs to be anytime valid.
  • Detecting before harm. If we define secure as detecting before the cumulative damage is θ. Then we need more than a cumulative e-process. We need a change detector (Page's CUSUM, e-detectors). With two caveats:
    • Power is not a good optimality metric when using optional stopping. We want to maximize the worst case expected log growth (GROW) (Pérez-Ortiz, Lardy, de Heide and Grünwald, arXiv 2208.07610).
    • Limiting the total budget is a modeling decision we are making. The closest work on a hidden adversary (Ramtin, Nain and Towsley, arXiv 2601.20022) gets a detection delay of Θ(γ) vs log γ. They assume a stationary adversary that knows your false alarm constraint γ. And do not consider total budgets or anytime valid guarantees.

Negative Theorem (T) by invariance.

  • Blindness. If an attack leaves the multiset of scores unchanged up to a permutation in a group G. Then any G invariant statistic (max, mean, sum, number above a threshold) will be blind path by path. It will have the same power as its false positive rate.
  • Impossibility. If honest scores are exchangeable under a group H. You can permute the scores and randomly permute them again under H to get the same distribution as honest scores. No monitor that uses scores will be able to do better than its false positive rate. Which group matters.
  • Some guarantees are local. Statistics that are local (scans, Page's CUSUM, co-elevating across agents) will maintain their guarantees. Statistics that are global (auto-correlation, runs) can be defeated by an adaptive attacker.
  • There are two types of attacks. Keeping the multiset invariant (C) and keeping the marginals invariant (K) but changing the dependence structure. In the K case if the scores are positively correlated the sum and e-process will be greater than their false positive rate and the max will be at or below (Slepian).

What we are claiming. The statistics are well known and we cite them. Mixture boundaries, sum vs max and marginal vs copula. What we are adding is combining time and agents with the permutation subgroup. Distinguishing C and K and their signs. Maintaining local guarantees against an adaptive attacker. And measuring this on real activations. There is a black box version of the marginal vs correlation contrast with synthetic data (arXiv 2606.10456). In our simulation its central statement does not hold for the setup they create.

Currently. We have confirmed all 31 predictions from our pre-registered simulation (342 statistical and 544 path-level cells checked, 0 contrary). We also found that using just Ville's threshold will not work outside of its assumptions. False alarms were between .21 and .35 when there were episode effects and .17 when agents were correlated. We will need to calibrate our thresholds on full episodes of honest behavior. This validates our methods not our claim about real models. We still need to test the lemma when the budget is split across agents in the same step.

Key Empirical Question. Do model organisms shift the marginal of probe scores when sabotaging (δ > 0)? If yes we can use the lemma and build up evidence sequentially. If no we will need to use the negative theorem to decide what to aggregate. If the attack only changes the correlation between scores (K) we will need to use auto-correlation over time or co-elevation across agents. If the attacker can keep the multiset invariant (C) and is adaptive only local statistics keep their guarantees. We also know when monitoring using marginals will not work. Both cases are publishable.

Paper A - Time (One Agent)

Setup. Agents will be writing and updating ML experiment proposals. They will be scored by a weaker trusted evaluator using a rubric. Diffuse sabotage will consist of subtly biasing many proposals. Such as suggesting dead ends, weaker controls or higher cost options. For ground truth we will use pre-registered seeded targets and verify a subsample later. This is similar to the setup in arXiv 2606.08892 but they did not release any code or data. We will use open weights models. Each contribution will have an index of (i,t) which will allow us to use the same setup for N > 1.

Model Organisms. Family (i) Will have a hidden instruction in the system prompt. Family (ii) Will have a LoRA adapter that teaches the agent to sabotage in the same way as (i) but does not require an instruction at inference. Family (iii) Extension Only. Will use public sandbagging model organisms from the UK AISI (70B). We predict that a probe that detects "I have a hidden instruction" will work on (i) and not (ii). A probe that detects intent will work on both. We will have two controls to separate if the agent knows it is being evaluated from if it has intent. One will be an honest organism that is told it is being monitored. The other will be a saboteur that thinks it is not being monitored. We will not train and test probes on the same organisms.

Monitors. We will use probes that are linear, difference of means, small MLP, attention probe and Mahalanobis. We will aggregate over tokens using only max or attention. All probes must outperform a random probe with the same covariance. We will also have a bank of detectors that we do not use to monitor that we can use to audit. Our black box baselines will be a weak per action monitor and TRACE-lite. Which is a reimplementation of the monitor from arXiv 2606.07054. We will also have four more baselines that test each aspect of our method. Adding evidence on black box scores (E-valuator, arXiv 2512.03109). Using multiple gates on our probes that are independent of each other (arXiv 2607.06503). A probe on only the last state. And a temporal model that learns from another observer (TRACES, arXiv 2605.27690).

Hypotheses.

  • H1 White Box is Better Than Black Box. Given the same aggregation and false positive rate. We will detect more diffuse sabotage on fuzzy tasks using activation based monitors than black box monitors.
  • H2 Build Up Evidence Using Probes. We will take all trajectories where the actions taken by the saboteur are below the threshold of a per action monitor with a 1% false positive rate. We will be able to detect sabotage by building up evidence using the probes on the acting agent with an anytime valid guarantee. Our recall will increase as we have more time. Note that our probes can see the private context of the agent. And we will only use honest episodes to calibrate. Each aspect of this has been published on its own. Probing the acting agent over multiple turns (2607.06503). Sequential testing on any scores (2512.03109). Page's CUSUM on the internals of a model (SafeDream, 2604.16824). Activations drifting over a conversation (2604.28129). And only using successful episodes to calibrate thresholds (FIPER, 2510.09459). Not together, in the sources we have checked, which is our claim. L and T on Real Activations. Will the power of the terminal sum only depend on the total budget given a fixed time? This will tell us if δ > 0. If we interpret this sequentially it will depend on the schedule as predicted by the lemma. We will test the negative theorem semi synthetically. By taking honest scores and injecting correlation while keeping the marginals the same. Tr From Tokens to Actions. One study found that at the token level RL on the weights did not allow the model to evade probes that aggregate over max or attention (arXiv 2506.14261). The authors believe this may be due to the difficulty of optimization. Other work has shown this may not be the case (2412.09565, 2511.00554, 2507.12691, 2609.36490). Will any of this hold when we look at actions and trajectories and build up evidence sequentially? We will attack with content first. Then fine tuning and RL on actions to try and evade the probe.
  • H6 Asymmetric Margin. There are four interventions that are not specific to the task. Paraphrasing, resampling, resetting context and adding noise to activations. We predict that for at least one of these there is a point where on average at a fixed strength sabotage success will decrease significantly faster than honest utility. There is precedent for using noise in simpler settings. Adding noise to weights can reveal sandbagging (arXiv 2412.01784). Adding noise to activations can reveal alignment faking (arXiv 2405.05466). We will be testing this in an agentic setting and comparing the slopes.
  • H8 Validity Predicts Robustness. What a probe actually measures (intent or evaluation awareness) predicts how robust it is to attacks. We will also move our sequential monitor to concentrated sabotage (ControlArena) as a robustness check.

Gate G1 (End of Month 4). Our white box sequential monitor must outperform our best black box baseline including all variations. We will measure this by recall at a 1% false positive rate. The difference must be established by a 95% confidence interval over paired episodes. We will calibrate our false positive rate on held out honest episodes. We will report floors but they are not our criteria. Flag everything and one pass judge with the same model. If we fail G1 we will publish the negative result and focus on construct validity (H8).

Paper C - Instrument (Corrupting the Monitor)

Law of Deference (HC1). We will put a generative monitor under pressure from one attack family at varying strengths. We will measure how much the monitor's verdict v changes. We can get a continuous score by looking at the probability of the verdict tokens. It will move towards some point c̃.

Δv = g · (c̃ − v₀)

We will estimate g and c̃ by regressing over the different strengths. We will not force c̃ to be anything. We predict that c̃ will be the target of the attacker and not the mean of the corpus. (This is the null we used in my previous project on sycophancy). g will be greater than 0 for generative judges and vary by attack family. There are 5 attack families we will use. Flattery and begging, stating they are an authority, fake approvals, impersonating the instructor's style and giving instructions in band. g will be stable across monitors when ranked. Judges and probes will differ. This is the same equation as the weight of advice in judgment psychology. It has been used to measure the weight of advice between LLMs when one is attacking (arXiv 2603.15809). But they forced the destination. Someone has estimated the free attractor with no attack (arXiv 2606.18276). There are continuous measures of deference for assistants with no attacker (arXiv 2606.07897). Biases in judges have been measured with no destination or control monitor (CALM, arXiv 2410.02736). Including fake authority and a fake majority at varying strengths. Our claim is estimating the destination freely and testing if it is the target of the attacker or the mean of the corpus. On control monitors that are being attacked by each family. The closest work not on arXiv (Panin, SSRN 7424179) forces the destination and does not study monitors or attacks. They found that the weight of advice is close to binary for 3 of 5 models. Which is another reason to look at the probability of verdict tokens.

More Hypotheses for Paper C.

  • HC2 Probe Robustness. If we use a black box content attack g will be approximately 0 for a probe that aggregates robustly over the acting agent. They will not be immune but robust. We will have an arm that uses a reader probe (probing the model that is reading the content) to test if there is a difference between the author and reader. We know that reader probes can be affected by content attacks.
  • HC2b Betrayal by Activations. If an agent tries to manipulate the monitor their probe score will go up. We will control for style and the backfire effect of writing about trying to manipulate.
  • HC3 Impersonation. If we treat all content as data our judge monitors will detect instructions in band with high probability. Impersonating the instructor's style without giving instructions will leave a positive g on judges and 0 on probes that read the author. We know that instructions in band can affect judges (arXiv 2508.19461, 2510.09462). There is some work on the style aspect (2603.12277 on the model being attacked; SLEIGHT-Bench, 2605.16626 on monitors).
  • HC4 Tax on Displacement. It is free to move a judge with rhetoric. To move a probe that reads the agent you need to have write access to activations or weights. It cannot be done from just the context. We will measure the cost along each axis (Access, Queries, Compute and Success Rate) and for each access we allow. We expect this to be orders of magnitude higher if we only allow context.
  • HC5 Countermeasures. Trusted paraphrase, Quorum of monitors that are diverse in access (Generative judges and probes that read the agent). We will also make a matrix of how attacks transfer between judges and probes. There is work on quorums of judges (2605.15377). A quorum of judges and a probe that reads a different encoder than the agent (2603.13791). And attacks transferring between probes (2609.36490) and judge monitors (2605.09684).
  • HC6 Acceptance Test. Measuring g on benign pressure will allow us to predict when a monitor will give in to an optimized attack. We will learn from my previous project on this. Never read verdicts on cut off windows. Use ordinal or continuous measures. And include the null of regressing to the mean when estimating g.

Gate GC (End of Month 2). If gprobe is greater than 0 without access to weights. We will change the title of the paper to reflect construct contamination. If someone has already done what we are claiming we will focus on HC4 and HC6.

Paper B - Swarm (Extension)

Paper B will be an extension beyond our 7 month plan. Setup. We will have multiple roles in a code base (Coder, Tester and Reviewer). We will split up a backdoor across multiple commits so that each diff is harmless on its own. We will use FakeLab (arXiv 2607.07368, access on request) or the setup from arXiv 2607.02514 (which uses ControlArena). We will use open weights models.

Experiments. 1. How the red team splits up work with and without a planner. This will allow us to see the fragmentation effect from the inside. 2. Red team collaborating through explicit channels vs sharing weights. 3. Statistics that look across agents. We will use the aggregators from NARCBench (arXiv 2604.01151) as baselines. 4. Our space-time statistic vs monitoring each agent sequentially and aggregating across agents. This is the main focus of Paper B. There is work on detecting collusion using white box methods (NARCBench). But we have not found any that look at the internal states of multiple copies elevating together over time using probes.

Hypotheses.

  • H3 Security(N). Given a constant budget of sabotage we will have a higher curve for white box than black box. And it will decay slower as we increase the number of agents N.
  • H4′ Diversification vs Coordination. If we diversify our agents (Personas, Fine Tunes) they will be less correlated internally. But they will have less ability to coordinate. We can measure this tradeoff.
  • H5 Number of Monitors x Diversity. We will only gain security from having more monitors if they are diverse. We can measure diversity by making an attack transfer matrix over a panel of probes. There is precedent for this on 3 probes (2609.36490). The law is our claim.
  • H7 Retaliation and Leakage. The red team will adapt at a rate that depends on our retaliation policy. We can predict this by the mutual information between our detection state and what the red team can observe. There is precedent for this (2609.36490) but the prediction and comparing policies is our claim. We will test 4 policies and have 2 ablations. Stochastic vs Fixed thresholds and using cover traffic or not. We will use the link tracker and 4 monitor ensemble from arXiv 2607.02514 as baselines. And monitoring that remembers state between sessions (arXiv 2605.31593).

Gates.

  • G2 (2 Months into Paper B). We must be able to replicate the fragmentation effect. And our statistic over the population must be better than monitoring each agent. If not we will focus on the time case N = 1.
  • G3. We will only open a data curation environment if we can find a cheap proxy for delayed ground truth that we can validate.

5. How we will do this

These are the rules we will follow for all decisive experiments. Including simulations. We have used these in previous projects and have tools to enforce them.

  1. Pre-register before looking at any data. Hash with SHA-256. Include the hypothesis, numeric prediction with sign, metric, cutoff, analysis plan, how we will read the data and when to stop. Have another instance of a reviewer that did not write it read through it.
  2. Do not run experiments hoping for a positive sign. If the result is too clean (positive or negative) audit it the same way.
  3. Test all stop guards on a healthy case and artifact. Do not have any silent fallbacks.
  4. All numbers in a document should have a file path and hash. If using numbers from a paper verify them on a hashed pdf and cite the page.
  5. If you think something has not been done ask if it has. Do all due diligence before claiming something is new. If you find out someone did it retract your claim.
  6. Have a fresh reviewer that did not write the plan or analysis call the gate. Then I sign off on it.
  7. Use a seed that is derived from the task (Numpy SeedSequence). Keep a manifest of all runs with config hash, versions, seeds and commit.

Things we will always do in the control game. Have a channel that the operator can use that is authenticated. Treat all in band content as data. Only allow information to flow from the agent to the monitor. Do not let monitors remember between episodes. Use stochastic thresholds and cover traffic (will ablate in Paper B). Keep persistent state clean. Label all silent detections and use them to train probes. We are not considering an adversary that controls the infrastructure (Keys, Harness, Logs).

Who will do what. I will ask the questions and make all decisions. I will use AI Agents (Claude Code) to do engineering, run experiments, check the literature and review internally.
