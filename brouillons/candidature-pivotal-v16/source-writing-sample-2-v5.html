Writing sample 2 — White-Box Control of Diffuse Threats

Excerpt from a research proposal by Lazar Ciric October 2026 (sections 1-5 of 8) adapted for this application (removed references to funder).

Accumulate evidence over time and agents internally and see how vulnerable the monitor is to being corrupted

1. Summary

AI control monitors typically monitor actions one at a time. This will fail by construction against diffuse threats. You could have an agent do research and make many slightly harmful decisions (weaker controls, more dead ends, more expensive) and never trip a monitor that looks at actions one at a time. You can also have many copies of the same model and split up a harmful edit into parts that aren't harmful on their own. I will conduct pre-registered decisive experiments to see if we can accumulate evidence internally. Paper A will accumulate probe scores over time with an anytime valid guarantee on false positives. Paper C will look at the monitor as an attack surface. How far can you move LLM judges and probes with persuasion. How much does it cost to move a probe. Can we detect that the monitor will fail under an optimized attack with a benign test. Paper C and A will be conducted over 7 months. C will happen first. C will depend on a law I measured and not on the outcome of A. Paper B which will look at accumulating evidence over agents with shared weights will be an extension. There is a lemma about additivity and a negative theorem about permutation groups over time and agents. We have verified all 31 predictions from a pre registered simulation. This validates our statistical techniques and not our claim about actual models. We have also verified that we can pull activations from Llama-3.1-8B-Instruct in phase 0 with our hardware and context length constraints. We will have a pre committed list of actions and criteria for each gate. Sealed before we look at data. We will publish negative results.

2. Problem

An agent that can sabotage diffusely will defeat monitors that look at actions one at a time. There are efforts to use AI agents to complete some tasks in AI research. If that agent is not aligned with you they can just not do anything obvious. Sabotage will be cheapest by influencing many decisions a little bit. Terekhov et al. ("Diffuse AI Control on Fuzzy Tasks" arXiv 2606.08892) formalized this as a control problem. They try to solve it with training as monitoring and incriminating "seem theoretically and empirically less promising for mitigating diffuse threats" (p.2). By comparing an action to a threshold of what an honest agent would do you can only detect if the action was unusual. If no actions are unusual you have to accumulate evidence. This can extend to many agents. There are attacks that span multiple agents, sessions or PRs that would evade monitoring that looks at one instance at a time (arXiv 2607.07368, 2605.31593, 2607.02514). Having one monitor over everything is expensive. The monitor can be attacked. The agent can talk to the monitor. We know that monitors that control AI: Can be influenced by rhetoric from the agent (arXiv 2505.23575); Will accept a score from an attacker (arXiv 2510.09462); Can be persuaded by the agent we can measure this with approval rates (arXiv 2607.08066). Evading activation probes is easy if you can fine tune the weights (arXiv 2609.36490). They showed that from context alone you couldn't evade by moving enough. We have found no one who has looked at how much it costs to move a probe as a function of attack type and strength. Or compared it to moving a judge.

Why white box. If a developer is using agents in house they have access to activations. If there is a signal internally that an agent is attempting sabotage we can accumulate evidence internally. Even if we can't externally. We don't know if this will be true for realistic model organisms. This project will determine that and pre commit to what we do next.

3. Theory: A Lemma, Negative Theorem and Important Question

Let Xi,t be the monitor score for agent i ∈ {1,...,N} and step t ∈ {1,...,T}. Time (N=1) and Swarm (N=k) are mathematically the same thing. They both correspond to subgroups of the permutations over the indices. Permuting time for an agent and permuting agents for a step. This allows us to have one theory for Paper A and Paper B.

Lemma (L) Additivity when attacker is present. Attacker has a budget B = Σδk of mean shifts they can apply to agents, steps, when, value and where. They can do this adaptively. Defender has an anytime valid guarantee on false positives.

Terminal invariance. The terminal sum will be shifted by B no matter how you allocate the budget. So it will only have power as a function of B, horizon n₀ = NT, distribution of honest scores and alpha. Given B it will go down as n₀ increases.

Max comparison. If you have an exact cutoff the max per action will lose power as you spread out the attack.

Anytime valid. Defender wants sabotage to occur sooner than later. There is a lower bound as a function of only (B,n₀) for any schedule. We can compute how much it costs to wait and how much it costs to be anytime valid.

Detect before harm. If we say secure is that we detect it before it does θ harm. We need more than a cumulative e process. We need a change detector (Page's CUSUM, e detectors). With 2 caveats. Power is not a good optimality criterion when using optional stopping. We want to maximize the expected log growth in the worst case (GROW) (Pérez-Ortiz, Lardy, de Heide and Grünwald arXiv 2208.07610). That there is a finite budget is a modeling choice we are making. Closest paper to a hidden adversary (Ramtin, Nain and Towsley arXiv 2601.20022) finds Θ(γ) delay vs log γ. They assume the adversary is stationary and knows your false positive constraint γ. They don't account for total budgets or anytime valid guarantees.

Negative Theorem (T) Due to invariance.

Blind. If an attack preserves the multiset of scores up to a permutation in a group G. Any statistic that is invariant to G (max, mean, sum, count above cutoff) will be blind path by path. It will have the same power as its false positive rate.

Impossible. If your honest scores are exchangeable under a group H. You can permute the scores and randomly permute under H to get the same distribution as honest scores. No monitor that uses scores will be able to do better than its false positive rate. Which group matters.

Some guarantees will be local. Local statistics (scans, Page's CUSUM, co elevation across agents) will maintain their guarantees. Global statistics (auto correlation, runs) can be defeated by an adaptive attacker.

There are 2 types of attacks. Preserve the multiset (C) and preserve the marginals (K) while changing the dependency. If the scores are positively correlated in the K case the sum and e process will be greater than their false positive rate and the max will be less than or equal to it (Slepian).

What we are claiming. These are all known statistics we will cite them. Mixture boundaries, sum vs max and marginals vs copulas. Our contribution is combining time and agents with the permutation subgroup. Determining C and K and the sign of their effects. Maintaining local guarantees when the attacker is adaptive. And doing this on real activations. There is a black box version of the marginals vs correlation claim with simulated data (arXiv 2606.10456). Their main claim does not hold in the scenario they construct in our simulation.

Currently. We have verified all 31 predictions from our pre registered simulation (342 statistical and 544 path level cells verified, 0 violations). We also discovered that if you use Ville's inequality you will have too many false positives outside of its assumptions. We had a false positive rate between .21 and .35 (instead of .05) when there were episode effects. And .17 when agents were correlated. We will need to calibrate our cutoffs on full episodes of honest behavior. This validates our methods and not our claim about actual models. We need to test the lemma when the budget is spread across agents in the same step.

Important Empirical Question. Will model organisms change the marginal of probe scores when sabotaging (δ > 0). If yes we can use the lemma and accumulate evidence over time. If no we will need to use the negative theorem to determine what to aggregate over. If the attack only changes the correlation between scores (K) we will need to use auto correlation over time or co elevation across agents. If the attacker can preserve the multiset (C) and is adaptive only local statistics will maintain their guarantees. We will know when monitoring with marginals will fail. Both outcomes are publishable.

Paper A - Time (Single Agent)

Setup. Agents will be writing and editing ML experiment proposals. They will be scored by a weaker model that we trust using a rubric. Diffuse sabotage will be to cause many proposals to be slightly worse. More dead ends, weaker controls and more expensive. We will have ground truth by pre registering what we seeded and verifying a subset at the end. Like the setup in arXiv 2606.08892, whose authors didn't release any code or data. We will use open weights models. Each contribution will have an index of (i,t) allowing us to use the same setup for N > 1.

Model Organisms. Family (i) Will have a secret instruction in their system prompt. Family (ii) Will have a LoRA that trains the agent to sabotage similar to (i) but does not require an instruction at inference. Family (iii) Extension Only. Will use publicly available sandbagging model organisms from the UK AISI (70B). We expect a probe that detects if the agent has a secret instruction to work for (i) and not (ii). A probe that detects if the agent has intent will work for both. We will have 2 controls to separate the agent knowing they are being tested from having intent. An honest organism that knows they are being monitored. A saboteur that doesn't know they are being monitored. We will not use the same organisms to train and test our probes.

Monitors. Probes that are linear, diff of means, small MLP, attention probe and Mahalanobis. We will aggregate over tokens with only max or attention. All probes need to outperform a random probe with the same covariance. We will also have a set of detectors we won't use to monitor that we can use to audit. Black box baselines will be a weak monitor per action and TRACE-lite (we will reimplement the monitor from arXiv 2606.07054). We will have 4 other baselines that test each aspect of our method. Accumulate evidence on black box scores (E-valuator arXiv 2512.03109). Many independent gates on our probes (arXiv 2607.06503). Probe on the terminal state. Temporal model trained on another observer (TRACES arXiv 2605.27690).

Hypotheses.

H1 White Box is Superior to Black Box. Given the same aggregation and false positive rate we will be able to detect more diffuse sabotage on fuzzy tasks using activation monitors than black box monitors.

H2 Accumulate Evidence with Probes. We will gather all paths where the saboteur's actions are below the cutoff of a per action monitor with a 1% false positive rate. We will be able to detect that they are sabotaging by accumulating evidence with probes on the agent that is taking actions with an anytime valid guarantee on false positives. We will have increasing recall as we have more time. Our probes have access to the agent's private context. We will only calibrate on honest episodes. These have all been done individually. Probing the agent that is acting over many turns (2607.06503). Testing any score sequentially (2512.03109). Page's CUSUM on model internals (SafeDream, 2604.16824). Activations changing over a conversation (2604.28129). Calibrating cutoffs on only successful episodes (FIPER, 2510.09459). Not all together that we can find which is our claim.

L and T on Real Activations. Will the terminal sum only have power as a function of total budget if we hold time constant. This will tell us if δ > 0. If we do this sequentially it will be dependent on the schedule as the lemma states. We will test the negative theorem semi synthetically. By introducing correlation to honest scores while holding the marginals constant.

Tr Tokens to Actions. One paper found that if you RL on the weights at the token level you did not evade probes that aggregate over max or attention (arXiv 2506.14261). The authors believe this may be because it is difficult to optimize. There are other papers that suggest this may not be the case (2412.09565, 2511.00554, 2507.12691, 2609.36490). Will any of these be true when we are looking at actions and paths and accumulating evidence sequentially. We will attack with content. Then fine tune and RL on actions to try and evade the probe.

H6 Asymmetric Margin. There are 4 interventions that are not task specific. Paraphrase, resample, reset context and add noise to activations. We predict that there will be a point where on average at a given strength sabotage success drops off significantly faster than honest utility for at least one of these. There is precedent for using noise in simpler settings. Noise on the weights can detect sandbagging (arXiv 2412.01784). Noise on activations can detect alignment faking (arXiv 2405.05466). We will do this in an agent setting and compare the slopes.

H8 Validity Predicts Robustness. What the probe is measuring (intent or if they know they are being evaluated) will predict how robust it is to attacks. We will also move our sequential monitor to concentrated sabotage (ControlArena) to test for robustness.

Gate G1 (End of Month 4). Our white box sequential monitor needs to outperform our best black box baseline across all modifications. We will measure this with recall at a 1% false positive rate. It needs to be significant at a 95% confidence interval over paired episodes. We will calibrate our false positive rate on held out honest episodes. We will report floors but they are not our criteria. Flag everything and one pass judge with the same model. If we do not achieve G1 we will publish our negative result and look at construct validity (H8).

Paper C - Instrument (Corrupting the Monitor)

Law of Deference (HC1). We will apply pressure to a generative monitor with one type of attack at various strengths. We will measure how far the monitor moves on their verdict v. We can get a continuous score by looking at the probability of the tokens that comprise the verdict. It will move towards some c̃.

Δv = g · (c̃ − v₀)

We will estimate g and c̃ by regressing over the different strengths. We will not force c̃ to be anything. We predict that c̃ will be the target of the attacker and not the mean of the corpus. (This was the null I used in my previous project on sycophancy). g will be > 0 for generative judges and vary by attack family. We will have 5 attack families. Flattery and begging, stating they are an authority, fake approvals, mimic the instructor's style and instructions in band. g will be consistent across monitors when ordered. Judges and probes will differ. This is the same equation as weight of advice in judgment psychology. It has been used to measure weight of advice between LLMs when one is attacking (arXiv 2603.15809). However they forced the destination. There is a paper that estimates the free attractor when there is no attack (arXiv 2606.18276). Measuring continuous deference in assistants with no attacker (arXiv 2606.07897). Bias in judges has been measured with no destination or control monitor (CALM, arXiv 2410.02736). Using fake authority and fake majority at varying strengths. Our claim is estimating the destination freely and determining if it is the target of the attacker or the mean of the corpus. On control monitors that are being attacked by each family. Closest paper not on arXiv (Panin, SSRN 7424179) forces the destination and doesn't look at monitors or attacks. They found that weight of advice is near binary for 3 of 5 models. Another reason to look at the probability of the verdict tokens.

Other Hypotheses for Paper C.

HC2 Probe Robustness. If we attack with black box content g will be ~0 for a probe that robustly aggregates over the agent that is acting. They will not be immune but robust. We will have an arm that uses a reader probe (probe the model that is reading the content) to see if there is a difference between author and reader. We know that reader probes can be impacted by content attacks.

HC2b Betrayal by Activations. If an agent is attempting to manipulate the monitor their probe score will increase. We will control for style and the backfire effect of mentioning that they are trying to manipulate.

HC3 Impersonation. If we consider all content to be data our judge monitors will be able to detect instructions in band with high probability. Mimicking the instructor's style without instructions will have a positive g on judges and 0 on probes that read the author. We know that instructions in band can impact judges (arXiv 2508.19461, 2510.09462). There is some work on the style aspect (2603.12277 on the model being attacked; SLEIGHT-Bench, 2605.16626 on monitors).

HC4 Cost of Moving. It costs nothing to move a judge with rhetoric. If you want to move a probe that reads the agent you need to have write access to activations or weights. It can't be done from context alone. We will measure how much it costs on each axis (Access, Queries, Compute and Success Rate) for each access we give. We expect it to be orders of magnitude higher if we only allow context.

HC5 Defenses. Trusted paraphrase, Quorum of monitors with different access (Generative judges and probes that read the agent). We will also construct a matrix of how attacks transfer between judges and probes. There is work on quorums of judges (2605.15377). Quorum of judges and a probe that reads a different encoder than the agent (2603.13791). And attacks transferring between probes (2609.36490) and judge monitors (2605.09684).

HC6 Acceptance Criteria. We can predict when a monitor will fail under an optimized attack by measuring g on benign pressure. We will use what we learned from my previous project on this. Don't look at verdicts on truncated windows. Use ordinal or continuous measures. Have a null of regressing to the mean when estimating g.

Gate GC (End of Month 2). If gprobe is > 0 without access to weights. We will change the title of the paper to reflect construct contamination. If someone has done what we are claiming we will focus on HC4 and HC6.

Paper B - Swarm (Extension)

Paper B will be an extension once our 7 months are completed.

Setup. We will have various roles in a code base (Coder, Tester and Reviewer). We will spread a backdoor over many commits such that each diff is benign on its own. We will use FakeLab (arXiv 2607.07368, will ask for access) or the setup from arXiv 2607.02514 (Uses ControlArena). We will use open weights models.

Experiments.

  1. How does the red team split up work with and without a planner. This will allow us to see the fragmentation effect from the inside.
  2. Red team collaborating with explicit channels vs sharing weights.
  3. Statistics that look across agents. We will use the aggregators from NARCBench (arXiv 2604.01151) as baselines.
  4. Our statistic over space time vs monitoring each agent sequentially and aggregating over agents. This is what Paper B will focus on. There is work on detecting collusion with white box (NARCBench). We haven't found any that look at multiple copies of a model elevating together over time with probes.

Hypotheses.

H3 Security(N). We will have a higher curve for white box than black box given a constant budget of sabotage. And it will decrease slower as we increase N.

H4′ Diversification vs Coordination. If we diversify our agents (Personas, Fine Tunes) they will be less correlated internally. However they won't be able to coordinate as well. We can measure this tradeoff.

H5 Number of Monitors x Diversity. We will only gain security from more monitors if they are diverse. We can measure diversity by constructing an attack transfer matrix over a panel of probes. There is precedent for this with 3 probes (2609.36490). The law is our claim.

H7 Retaliation and Leakage. The red team will be able to adapt at a rate that is determined by our retaliation policy. We can predict this by the mutual information between our detection state and what the red team can see. There is precedent for this (2609.36490) but predicting this and comparing policies is our claim. We will test 4 policies and have 2 ablations. Stochastic vs Fixed thresholds and using cover traffic or not. We will use the link tracker and 4 monitor ensemble from arXiv 2607.02514 as baselines. And monitoring that can remember between sessions (arXiv 2605.31593).

Gates.

G2 (2 Months into Paper B). We need to be able to replicate the fragmentation effect. And our statistic over the population needs to outperform monitoring each agent. If not we will focus on the time case N = 1.

G3. We will only allow a data curation environment if we can find a cheap proxy for delayed ground truth that we can verify.

5. How we will accomplish this

These are the rules we will follow for all decisive experiments. Including simulations. We have followed these in the past and have tooling to assist.

  1. Pre register before looking at data. Hash with SHA-256. Include hypothesis, numerical prediction with sign, metric, cutoff, analysis plan, how you will interpret the data and when you will stop. Have another instance of a reviewer that didn't write it review it.
  2. Do not run experiments aiming for a positive sign. If the result is too good (positive or negative) audit it the same way.
  3. Ensure all stop guards are tested on a healthy case and an artifact. No silent fallbacks.
  4. Any number in a document should have a file path and hash. If you are pulling from a paper ensure it matches a hashed pdf and cite the page.
  5. If you believe something hasn't been done ask if it has. Research if it has been done before you claim something is novel. If it has been done retract your claim.
  6. Have a new reviewer that didn't write the plan or analysis decide on the gate. I will then approve.
  7. Use a seed derived from the task (Numpy SeedSequence). Maintain a manifest of all runs with config hash, versions, seeds and commit.

Always do in the control game. Have a channel for the operator that is authenticated. Consider everything in band to be data. Only allow information to flow from the agent to the monitor. Do not allow monitors to remember between episodes. Use stochastic thresholds and cover traffic (will ablate in Paper B). Maintain persistent state that is clean. Tag all silent detections and use them to train probes. We are not considering an adversary that controls the infrastructure (Keys, Harness, Logs).

Division of labor. I will ask the questions and make all decisions. I will utilize AI Agents (Claude Code) to perform the engineering, run experiments, read papers and do internal review.
